## What happened

Eric read the four Dynatrace traces of the four-runtime certification (Java/Rust edges → Python/Node
`llm.stream`) and reported the trees broken: no `http.request` first leg, an orphaned `async.http.request`,
"the caller starts with REST automation hitting http.flow.adapter and that should be the first leg and the
spans should be connected until it returns at async.http.response".

**Investigation (from the drive logs' datasets + code):** three causes.
1. The drive's `traceparent` header fabricated a random parent span nobody exported, so every root had a
   missing parent — a drive artifact, not an engine defect (both engines honour an inbound traceparent by
   making its span the first function's parent; by design the edge minted no span of its own).
2. `EventEmitter.sendWithEventHttp` copied trace id/path onto the stream relay's `async.http.request`
   event but not the sender's span → the client leg executed with no parent (Java only; Rust's route was
   zero-traced through `skip.rpc.tracing`, so it emitted no span at all).
3. `AsyncHttpClient.SseRelay` synthesized raw token frames with no span and stamped the trace on them →
   one traced, unparented reply-lane span per token (Java only; Rust forwarded raw frames untraced).
Plus the design observation: no span covered the HTTP round trip — the SERVER span was the first
function's own execution (0.5 ms for a 6 s stream), so a backend's response time for the service was wrong.

**Eric's rulings:** Finding 2 → fix Java and lock-step Rust ("telemetry is operational readiness so this is
important not to have broken spans"); Finding 3 → trace the head and the tail of token streams, annotate the
eof record with the number of raw frames; and implement the round-trip span "in async.http.response" for
the milestone.

**Implemented (Java, branch `fix/connected-edge-spans`):**
- Edge round-trip record `service=http.request`: `HttpRouter.routeRequest` mints the span

  status, error)` emits the record on every completion path (single-shot writer, stream terminal, error
  writer, housekeeper timeout); `AsyncContextHolder` carries the trace fields, `startTime`/nanos, an error
  marker (in-band stream failures report their own status) and the data-frame counter.

## Lessons

- A drive that fabricates a `traceparent` fabricates a parent nobody exports: the backend renders every
  root as broken and the defect looks like the engine's. Send `X-Trace-Id` (or nothing) when there is no
  real upstream span.
- "Trace the head and the tail, never per token" is the rule for any streamed response: the lane's terminal
  record carries the count instead of a span per frame.
- The zero-traced/skip-list semantics differed between the engines (Rust zero-traced the HTTP client route,
  Java only skipped the RPC round_trip record) and only the stream relay's callback-mode execution exposed
  it — the RPC path had masked the difference for months.
- Seeing the trace tree in the backend UI found what the drive logs' "0 export failures" could not.
