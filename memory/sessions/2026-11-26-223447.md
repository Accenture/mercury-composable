  ends and is not cancelled; the node then fails with the second call's status and error, the handler is entered (or the
  run aborts with that status), and no further batch starts.
- **Tests first.** The harness of the earlier log became `ForEachFailureTest`: eight tests through the HTTP stack over

- **The fix, engine side.** `GraphLambdaFunction.requestInOrder` sends a batch and returns one response per request in
  request order - each matched by the correlation id the platform restores on a reply, a 408 for a request without one;
  `stageFanOutResponses` stages a batch in list order and writes the node's status only until the first failure.
  `GraphExtension` and `GraphTask` use both, stop after a batch with a failure and skip the output mappings.
  `GraphApiFetcher` does the same in its own loop, pairs each response with its own request for the after-features,
  maps nothing for a failed element, and stops its dictionary items at the first that fails, with and without
  `for_each`. A warning names the failing element and how many did not start. No change to platform-core.
