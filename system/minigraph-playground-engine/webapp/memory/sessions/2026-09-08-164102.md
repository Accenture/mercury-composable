2. **Node overlap elimination.** Diagnosis: `transformGraphData` set a fixed `height`
   (`nodeHeightForHandleCount`, typically 100px) on every React Flow node, so real content
   (measured 200–440px in tutorial-12) was hard-clipped by `.content { overflow: hidden }`;
   older bundles rendered content-height nodes over estimate-based positions — the overlap
   Eric screenshotted. Fix, three parts:
   - **Content-driven heights**: nodes no longer get a fixed `height`; `initialHeight`
     (content-aware estimate: header 40 + per-row 9 + 18/wrapped-line at 22 chars, calibrated
     within ~3px on tutorial-12) sizes the pre-measurement paint, `style.minHeight` keeps the
     handle-count floor. React Flow v12 drops `initialHeight` from inline styles after
     measurement (`getNodeInlineStyleDimensions`), so the DOM height follows content. A fixed
     `height` is only reintroduced by the user via NodeResizer.
   - **Measured re-layout**: new export `computeMeasuredPositions(data, measuredHeights)`
     re-runs the layout pipeline with real heights. GraphView applies it once per graphData
     when every node has `measured.height`, then re-fits via an `onInit`-captured instance.
     Guard for the refresh stale-window: each RF node's `data.properties` must be
     reference-identical to the current graphData node's (the transformer passes it through
     by reference; parsed payloads always allocate fresh objects). The done-ref also keeps the
     relayout from fighting later NodeResizer/drag changes.
   - **Bounded intrusion relief** (`relieveNodeIntrusions`, computeLayout step 4.5): with
     content heights a tall node (tutorial-4's 301px decision) is a wall no slot ordering
     routes a long edge around. Each pass finds the canonically-first remaining forward-edge
     intrusion (via `forwardBezierYRangeOverNode`, refactored out of
     `forwardBezierIntersectsNode`; offsets from the extracted `deriveFlowHandleOffsets`)
     and shifts the intruded node's column chain vertically by the minimal clearance
     (margin 16, ≤8 passes, gated by the same `collectGeometryPairs` budget as scoring so
     adversarial-scale graphs skip it).

10. **Connections are selectable + keyboard-deletable (Eric's follow-up):** click an edge
    (React Flow's built-in wide interaction path) → selected style (primary-blue stroke,
    `!important` because edge strokes are inline) → Delete/Backspace removes it. The key
    rides React Flow's delete pipeline (`deleteKeyCode` + `onBeforeDelete`) but the
    callback ALWAYS returns false — the backend owns mutations: selected edges (deduped
    per node pair — the backend command wipes all connections between a pair) fire
    `delete connection {a} and {b}` via the new `buildDeleteConnectionCommand`
    (+ `validateDeleteConnectionAliases`), sent with sendRawText like the clipboard-drop
    flow; the graph redraws from the backend's "{a} -> {b} removed" confirmation (already
    a `detectMutation` pattern). Selected NODES are deliberately ignored by the keyboard —
    node deletion keeps the confirmed context-menu flow — and returning false also fixes a
    latent bug where default Backspace let React Flow delete elements client-side only.

11. **Undo via compensating commands (Eric ratified frontend-only — "we want the backend to
    be lightweight, our minimalist design principle"):** the backend keeps no undo journal;
    every UI-initiated mutation captures a pre-mutation graphData snapshot and pushes
    inverse console commands (`src/graphActions/undoCommands.ts`, all through the
    minigraphCommandBuilder serialization boundary — unbuildable snapshots yield null =
    not undoable). Inverses: connection delete → re-`connect` every relation BOTH
    directions (the command wipes the pair bidirectionally); node edit → re-submit the
    pre-edit snapshot (update = full replace, exact); create node → delete; create
    connection → delete pair + restore prior relations; node delete → recreate +
    reconnect all touching relations. `useGraphUndo` (depth 20) sends inverses over the
    WS; graph redraws from confirmations. Triggers: Ctrl/Cmd+Z (skipped in inputs and
    while an authoring session is open — native text undo wins) + an Undo button in the
    mutation toasts (new ToastAction/durationMs support; toast-bound undo only fires if
    its entry is still newest, else "press Ctrl+Z to undo in order"). Invalidation is
    minimalist: disconnect + graph import only; collaborative interleaving keeps
    last-write-wins; console-typed commands are not tracked; relation properties are not
    restored (connect carries type only); batch node-delete is not undoable (v1). No
    redo. Gotchas: a window keydown handler's `event.target` can be a non-Element
    (document) — guard with `instanceof Element` before `.closest`. **Live-caught race
    (Eric's question about cascaded connections exposed it):** the backend can process a
    later single-line `connect` BEFORE an earlier multi-line `create node` from the same
    session completes ("node X not found") — the undo executor therefore PACES inverse
    commands, awaiting each command's `graph.mutation` confirmation on the bus (2.5s
    timeout so error replies can't hang the chain; `executingRef` guards concurrent
    undos). Node-delete undo verified live afterwards: fetcher + all 4 touching relations
    restored.
