- **The defect, precisely.** `clipboard/commandBuilder.ts` had a serializer of its own: every property became a `key[]=value` line (a list one line per element, a scalar in the same `[]` form).
  `GraphCommandService.getNodeProperties` hands each line to `MultiLevelMap.setElement`, which appends on the `[]` signature, so a pasted `skill` arrived as `["graph.api.fetcher"]` and the traveler read the
  route as `[graph.api.fetcher]`. The authoring path never had the problem: the node editor converts a node with `createEditNodeFormState` (lists to `key[i]`, maps to `path.key`, sorted as the engine's
  `edit node` sorts, indices shown as `[]`) and `minigraphCommandBuilder` writes `key=value` lines and `'''` blocks; undo already reused both.
- **The fix is reuse, not a second serializer.** `buildNodeCommand(verb, node)` now runs the editor's conversion and the authoring builder (`buildCreateNodeCommand` / `buildUpdateNodeCommand`), which makes
  `webapp/docs/architecture.md` decision 2 (every UI mutation builds its text through `minigraphCommandBuilder`) true for the clipboard as well. Accepted consequences: keys come out sorted like `edit node`
  (the old builder kept JSON order); `null` prints as the text `null` (the engine's own `edit node` prints `String.valueOf`); a node the grammar cannot carry (an empty list or map, a value containing `'''`,
  more than one type, a reserved alias, an oversized command) throws, and the two Playground handlers toast `Paste failed: …` instead of sending; the unused `buildConnectCommand` is gone.
