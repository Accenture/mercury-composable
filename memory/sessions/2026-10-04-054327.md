**The fix and the docs** (branch `fix/mapping-source-verbatim`, commit `97ccbbe6`, PR #503; the Rust twin is mercury #351, Increment 156).

- **Found while documenting.** A mapping source may embed a `{namespace.key}` reference that resolves before the source is read (a key segment, a list index,
  text in a constant or a plugin argument) - both engines did it, no guide said so (the lexical table even said "inside COMPUTE/IF expressions"). A probe
  session showed the defect: the six mapping call sites rendered through the expression renderer, whose boolean-operator heuristic quoted every text value when
  the source held `!`, `<`, `>`, `==`, `&&` or `||` (`text(Hello {input.body.name}!)` gave `Hello 'Peter'!`). It also showed what stays: an unresolved
  reference renders `null` (Event Script keeps a non-model brace pair verbatim), a target is literal (`-> output.body.{x}` writes a broken key path), and
  Event Script's bare `items[model.i]` index is not a graph mapping (use `items[{model.i}]`).
- **The engine change.** `GraphLambdaFunction.substituteMappingSource` quotes a text value only inside a JSONPath filter (`$.` with `@`, where it must read as
  a string literal); the six call sites use it (`handleDataMappingEntry`, `fillFetcherApiParameters`, `getForEachMapping`, `performOutputMapping`,
  `GraphTask.buildTaskRequest`, `GraphApiFetcher.performDictionaryOutputMapping`). Expressions and statement commands keep `substituteVarIfAny`.
- **The pin.** `unit-test-mapping-1` (byte-identical in both repos) and `GraphTaskTest#mappingSourceResolvesDynamicVariablesVerbatim`; the A-B-A negative
  control (old renderer restored) fails at `Hello 'Peter'!`. Claim `mapping-source-dynamic-variables` (`4.12.21+`). Engine module 178/0, playground example
  23/0, starter template 4/0 (the engine installed to the local Maven repository first, so `~/.m2` holds the fixed 4.12.20 engine until the merge).
- **The docs.** The grammar's "Dynamic keys and values in a source" (`#dynamic-keys`, with the rules above and "keep a fixed prefix before a request value"),
  the skills reference's keyed table (`#keyed-table`, the gate before `f:long`), the agent checklist, the data-mapper help, and the Event Script plugin table's
  `-1` for `int`/`long`/`float`/`double` on null or non-numeric input (verified in both engines' `str2*`). CHANGELOG Unreleased item 17 with a READ note.
  Bundle `index-Cv2pdvxg` → `index-Bz9k-ffR` via `release:all` (deployed and help-mirrored to the Rust repo); it differs from the old bundle only by the new
