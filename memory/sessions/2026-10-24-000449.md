**Title:** The companion endpoint reports a `create node` on an existing node as a failure

## Context

A driver of the synchronous companion endpoint (`POST /api/companion/{id}/sync`) revised a node by sending `create node`
again with the new statements. The engine answered with the line `node {name} already exists` and changed nothing, but
the endpoint returned `ok: true`, so the driver believed the node had changed. The request: make "already exists" an
error. It is released code, so it has its own branch from main, `fix/companion-already-exists`.

## The defect

`GraphCommandService.createNode` prints `node {name} already exists` for a name the model already holds and leaves the
node as it was. `PostCompanionCommandSync` decides `ok` by matching the output lines against error words (`ERROR:`,
`aborted`, `does not have`, `Invalid`, `not found`, `Please try 'help'`, `Syntax:`); the line matches none of them.

## What was done

- **`isErrorLine` also matches `isNodeAlreadyExists`:** a line that starts with `node ` and ends with
  ` already exists`. The match is on the line's shape, because the help pages of `import` and `export` use the words
  "already exists" in their prose, and a help command must stay `ok: true`.
- **`CompanionSyncTest.createOnAnExistingNodeIsAFailure`** (session `ws-990017-2`): the first create is `ok: true`; the
  second is `ok: false` with `node root already exists` as the error; `update node` is `ok: true`; `help import`, whose
  prose says "already exists", is `ok: true`.
- **Docs:** `command-reference.md`, section "create node / update node", one bullet: a create on an existing name changes
  nothing and the companion endpoint reports it with `ok: false`; `update node` replaces a node. The Playground's help
  pages are unchanged, so the webapp bundle needs no rebuild.
- **CHANGELOG** Unreleased Fixed 7, with an upgrade note.
- **Not done: the Rust twin.** The Rust port has the same gap: `crates/knowledge-graph/src/commands.rs` prints the same
  line and `crates/knowledge-graph/src/rest.rs` `is_error_line` has the same word list. The entry says "Java engine";
  the port catches up in its own pull request.
