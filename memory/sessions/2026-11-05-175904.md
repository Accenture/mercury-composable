## What was done (branch `feat/playground-panel-name`)

- The title is compiled into the bundle (`webapp/src/config/playgrounds.ts`), and `GetIndexHtml` serves
  `template/playground.html` as read at startup; the Rust engine serves the same file unchanged. So the bundle's
  `index.html` gained an empty `<meta name="playground-panel-name" content="">`, the Java function fills it from the
  property (escaped for an HTML attribute, trimmed; a blank value or a page without the tag leaves the page as
  built), and `src/utils/panelName.ts` shows it in place of the Minigraph config title (`titleFromServer`, Minigraph
  only). No `playground.*` key existed before ([[conv-config-key-not-value-and-parent]]).
- The bundle rebuilt with `npm run release` after checking `node_modules` against the lockfile; only the
  `index-*` chunk and its map changed ([[help-edit-needs-bundle-release]]). The Rust repo is not deployed: its page
  keeps the default until a twin fills the tag ([[playground-webapp-single-source]]), Eric's decision.
- Docs: the configuration reference (`playground.panel.name`), *Playground and companion*, the webapp's
  `build-test-deploy.md`; CHANGELOG Unreleased Added 1; fact [[playground-panel-name-meta]].
