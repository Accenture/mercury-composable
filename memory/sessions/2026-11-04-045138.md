## Decisions taken as defaults, for Eric's review in the PR

1. **A node's function gets the node's relay, not the caller's route.** The relay names the sender's graph and node,
   frames each event for the transport, lets a synchronous subgraph inherit without a declaration, and is drained
   before the terminal event.
2. **The WebSocket entry is off by default** (its path is outside the REST automation's authentication). The first
   frame is `{header, body}`, and one session runs one graph.
3. **A refused `return.path.routes` entry is logged and declares nothing.** The app still starts.
4. **Every finished stream ends with `done`.**
5. **The Kafka sample's partition comes from `cid`.**
6. **Tool events go in call order.**

## Findings and lessons

- **A drain test needs volume.** With 2 or 300 events, the relay always beat the multi-hop reply chain, so the
  no-drain control passed. At 5000 events it failed 3 runs of 3, while the drained run passed in 1.2 s. When a
  control does not fail, ask whether the test can see the race before concluding the mechanism is unneeded
  ([[otel-optional-service-and-negative-control]]).
- **A guard whose effect is a log line has no client-visible test.** The `AsyncHttpResponse` change removes a stack
  trace, and the stream ends the same either way. The test pins the behaviour, not the change.
- **Merging two branches that both added a block at the same anchor**, with a keep-both script, spliced two Java
  methods together, because the conflict region began mid-method. Read every resolved conflict, not just the marker
  count.
- **The S1845 scan must separate members from locals.** A regex on indentation flags locals. The real clashes were a
  method and a constant (`notification`/`NOTIFICATION`) and two fields (`cid`, `seq`) against map-key constants.
