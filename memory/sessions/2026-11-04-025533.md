## Built (branch `feat/agent-loop-ask-row`, commit `c576090b`, PR #606)

- **`ToolCatalog`:** a row field `ask` (true or false). An ask row has no route (`noRoute`) and no write mark; a row
  without `ask` still needs a route. The row field list in the error is "name, description, input_schema, route,
  strict, write and ask".
- **`AgentLoop`:** a fourth outcome, `ANSWER`. An ask call waits in every mode except `unattended`, where it goes back
  as "'name' asks a person, and this run has nobody to ask". The approval block shows it with `ask: true` and no
  route. On resume, a question's decision is exactly `{id, answer}` (`checkAnswer`) and a tool call's exactly
  `{id, approved, note}` (`checkApproval`); the answer goes back as the call's output, capped like any result, and the
  call log reports `answered`. A shown call that loses its `ask` mark, or a mode changed to `unattended`, is a mismatch.
- **Vectors:** 17 new cases, 98 loop cases and 29 schema cases. Negative controls: a question running in `auto`
  fails 2 cases, the answer dropped fails 3. Module: 137 tests, the coverage gate holds.
- **Docs:** README section "A question for a person"; spec section 7.3 and ruling 38 in round 7 (section 7.2 now
