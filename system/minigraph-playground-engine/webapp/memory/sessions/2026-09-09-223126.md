## What happened

Post-regression UX round on `feature/minimap-help-run-v2` (PR #341), directed by
Eric after his manual test; commit `29430893` on the PR branch. Four changes:

1. **JSON-Path is payload-only.** `PLAYGROUND_CONFIGS` drops `graph`/`graph-data`
   from the JSON-Path `tabs`, and RightPanel hides the tab strip entirely when a
   playground declares a single tab (nothing to switch between). No data-path
   changes needed: `normalizeRightTab` already normalizes stale persisted tab
   selections, and `useGraphData`'s auto-switch funnels through the same guard.

2. **The graph-run input modal became an in-place left-slot panel.**
   `MockUploadModal` → `MockUploadPanel` (git rename), following the NodeEditPanel
   contract exactly: renders in the console's slot, Esc / Cancel / success closes
   the session and the slot returns to its previous content, `consoleOpen` never
   mutated, the header Console button unwinds the panel first. Both entry points
   ride it (graph-run workflow AND the manual console-row re-open), so the
   Playground is back to zero modals. Title per Eric: **"▶ Mock Graph Input"** —
   we are mocking input for a dry-run, not adding ("Add Graph Input" retired);
   the `awaiting-input` disabled-reason now says "mock graph input panel".
   `useMockUploadModal` → `useMockUploadPanel` (open/queue/success mechanics
   unchanged); `useGraphRunWorkflow` untouched except the
   `isWorkflowInputModal` → `isWorkflowInputPanel` rename — the phase machine was
   already presentation-agnostic. Slot priority: node editor > upload panel >
   console (a hidden upload session survives and reappears when the editor closes).

3. **Minimap floating island, promo hint deleted.** `useMinimapHint.ts` and all
   hint plumbing removed (RightPanel's `minimapHintEligible` and GraphView's prop
   with it). The open minimap now renders as a draggable island: a grip title bar
   (`⠿ Minimap`, pointer events with window-level move/up listeners) moves it
   anywhere in the graph pane; position persists via localStorage
   (`graph-minimap-position`, default `{left: 50, bottom: 15}` beside the control
   stack) and re-clamps on pane resize (ResizeObserver on `offsetParent`).
   Key gotcha: React Flow's `<MiniMap>` renders its own absolutely-positioned
   `react-flow__panel` — neutralize with inline `style={{position: 'relative',
   margin: 0}}` so the island wrapper owns placement; the map surface keeps
   `pannable` viewport-dragging (only the grip drags the island). Chosen over the
   flow-outside-the-pane variant Eric also offered: works in every layout incl.
   fullscreen, no cross-panel coupling, never steals console/help space.

4. **Left panel default widths (Eric's spec):** console 40%, node editor 30%,
   mock input 30%. `LEFT_PANEL_DEFAULT_SIZES` + a mode-transition effect call the
   react-resizable-panels v4 imperative `panelRef.resize()` (one rAF deferred so
   a closed→open mount has its handle); `useDefaultLayout` gets
   `onlySaveAfterUserInteractions: true` so imperative resizes never overwrite the
   user's persisted drag. `panelLayoutKey` now carries the slot MODE, so the graph
   re-fits on the 40↔30 width changes. The right panel's first-mount default is
   the complement (60/40 with clipboard); the old `helpOpen` width ternary was
   dead weight — help splits vertically inside RightPanel.
