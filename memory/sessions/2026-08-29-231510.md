**Two design insights made the server side nearly free:** (1) the reply lane and
`async.http.response` share one handler resolving the request context by correlation
id — so `EventApiService` can bind a lane dynamically and the renderer frames the
dialect, with back-pressure/keep-alive/idle-touch/exactly-once release all inherited
(an atomic release claim in the holder closes the bind-vs-close race); (2) today's RPC
inbox already rewrites the relayed request's correlation id — rewriting it to the edge
requestId for lane addressing is exact parity, the target never saw the caller's cid
anyway.

**Wire dialect (D5 concretized):** envelope frames = `event: envelope` + one
base64-encoded serialized EventEnvelope (requester's wire format mirrored, `to`/
`reply_to` cleared so server route names never leak) for the head (the writer puts
head control on its first outgoing envelope — packing it verbatim satisfies "first
frame = head"), the terminals, and every escape-hatch trigger (Map/byte bodies, `\r`
text, custom headers, non-200 mid-stream status, name colliding with the reserved
word); raw SSE frames for plain text. Client submode (marker `x-event-api: stream` on
the async.http.request event): decode + D7 addressing rewrite + conformance guards —
raw-first frame → in-band 500 "Invalid event stream - missing envelope head";
transport end without a decoded terminal → 500 "Event stream ended without eof";
trailing frames after a terminal discarded; buffered (non-SSE) fallback preserves the
classic callback semantics including the tolerant REST-error unwrap.
