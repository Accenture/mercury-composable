## Eric's ruling and its implementation (third commit on PR #598)

Eric opened the branch as PR #598 and accepted the recommendation: drop the id override and the `latest` entries, keep the
pinned-version cache, retire `schema.registry.cache.ttl` "and pass it to Confluent as `latest.cache.ttl.sec`" - read as
both: the key no longer times a Mercury cache, and a value still set becomes `latest.cache.ttl.sec` unless the registry
template sets that key itself. The Rust port, its own implementation, follows the same mechanism (mercury #399,
Increment 193).

- `ManagedCacheSchemaRegistryClient` keeps only the version cache: `latest` resolves through Confluent's
  `getLatestSchemaMetadata`, the type through `getSchemaById` (Confluent's id cache). Its constructor drops the id cache.
- `SchemaCodec`: no id `ManagedCache`; `passRetiredCacheTtl` maps `<prefix>.cache.ttl` (any prefix) to
  `latest.cache.ttl.sec` in seconds with a `WARN`, leaves the template's own value alone, and passes nothing for a value
  that is not a duration (`Utility.getDurationInSeconds` answers -1, which Confluent would read as "never expire").
  `CACHE_NAME` became `DEFAULT_KEY_PREFIX` (it doubled as the default prefix; no other module referenced it). The
  startup line reports `latestCacheTtlSec`.
- Tests: `EmbeddedSchemaRegistry.lookups()` counts GETs; `SchemaCodecTest` asserts by lookup counts instead of
  `ManagedCache` entries, plus `theRetiredCacheTtlIsPassedOnAsTheLatestCacheTtl` (the test properties' `schema.zero`
  prefix with `0s`); `SchemaCodecRetiredCacheTtlTest` for the mapping's four cases; `KafkaFlowAutoStartTest` and
  twin-kafka's `SecondaryConsumerCodecTest` assert the `<prefix>.version` cache. Negative control: with the
  `passRetiredCacheTtl` call removed, the zero-TTL test fails (`expected: <4> but was: <3>`); restored, it passes.
- The retired key left the test fixtures of both modules and two examples (`sync-over-async-demo`, `twin-kafka-demo`); the
  bundled `schema-registry.properties` and twin-kafka's secondary template gain a commented `latest.cache.ttl.sec`. Docs:
  the guide's schema notes (a *retired* note), its keys table and consumer keys, the configuration reference, the
  twin-kafka guide. CHANGELOG Unreleased Changed 9 (with the upgrade note) and Documentation 2 rewritten to match.
- Verification: `mvn -o clean install` over the reactor, BUILD SUCCESS 6:48, 2798 tests, 0 failures, 3 skipped (2793
