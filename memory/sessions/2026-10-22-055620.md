## What was done

- **Surveyed both engines** (the Java side read directly, the Rust side through a read-only survey of `~/sandbox/mercury`).
  - **Java.**
    - `DataMappingHelper.validInputLhs` and `validOutputLhs` (lines 159 and 213) accept a `$` source on a prefix test only.
    - `CompileFlows` drops a TASK with an invalid mapping entry and registers the flow without it. It never rejects the
      flow for that (`addValidatedInputEntry`, `finalizeEntry`).
    - `GraphModelGate` and `GraphModelValidator` never parse a `$` source.
    - `GraphModelValidator` already walks the four mapping properties and `statement`, and serves CompileGraph, the
      packager and the Playground's `run` command.
  - **Rust.** `serde_json_path` is used only in `crates/event-script/src/mlm.rs`.
    - `json_path_query` (:166) discards the parse error, then the error of the bracketize retry through `.ok()?`. So an
      invalid path is indistinguishable from a missing value.
    - There is no compiled-query cache. The whole state is converted to JSON on every lookup.
    - `get_lhs_element` (`mapping.rs:101`) already returns a `Result`.
    - The gates are `model_gate::validate`, `model_validator.rs` and `validator.rs`. Each accepts `$` on a prefix test
      (:152, :168), and the flow compiler drops the task the same way Java's does (`compiler.rs:207-211`).
    - No test pins the silent null.
  - **The `$` surface.** A `$` source can appear in:
    - mapping entries;
    - `for_each`;
    - graph.task, fetcher and extension `input`;
    - `graph.math` `MAPPING:` sources and `{$...}` selectors in COMPUTE, CONDITION, DECIMAL, IF, RESET and DELAY, since
      the selector resolves through `getLhsOrConstant`;
    - fetcher dictionary defaults;
    - plugin arguments.
  - **The repository has no `$` source carrying a `{...}` or `[model.…]` reference,** apart from the RFC's own example in
    the docs.

  2. Placeholders chosen by where each reference lands, found by the scanner WP4 needs.
  3. Refusal follows each compiler's existing unit.
  4. On Rust, the error is also raised at evaluation, and `cts.json` runs against `serde_json_path`.
  5. A shared vector file and negative fixtures on both engines.
  6. Three decisions for Eric.

## Findings

- **The plugin-argument splitter, on both engines** (`splitTopLevelArguments`; Rust `split_top_level_arguments`,
  `mapping.rs:293`), counts only parentheses. A `$` argument with a comma inside brackets, `f:x($.a['b','c'])`, is cut in
  two. That is broken today. Left alone, it would make the gate refuse a valid query with a confusing position.
- **Rust's per-lookup parse and JSON conversion** are a performance item. It is outside WP3 and not raised as a thread.
