I posed two decisions with recommendations and built the recommended answers while he read. He agreed with both:
1. **Event Script, a text value bare in a filter.** Event Script has always inserted text as written, so `@.price >
   {model.min}` with the text `10` compares as a number; the RFC's rule (quote all text) would make it silently false. Event
   Script therefore keeps text that is already exactly one literal (a number, `true`, `false`, `null`, or a quoted string) as
   written and quotes any other text. The knowledge graph quotes all text, as it always has.
2. **A name.** It takes Mercury's dot-bracket key path (`items[0].name` works today in `$.input.body.{model.path}`), not only
   dotted names. Such a value can add only child and index steps.

## Findings

- **Rust's CHANGELOG had my WP3 item below the separator.** In #391, Changed 5 was appended at the end of the Unreleased section,
  below the `---` that closes it. The released sections still diffed empty, so the existing check missed it. WP4 restores the
  separator directly above `## Version 4.12.24`.
- **The backslash gap was not JSONPath-only.** The `graph.math` lexer reads a backslash as an escape, so `escapeVar` broke a
  quoted expression for `C:\temp` (a tab) or for a value ending with `\` (an unterminated literal). Both engines' lexers read
  the same escapes.
- **Nested references** inside a `$` source are refused on both engines although their brace scans differ: Java's
  `extractSegments` takes the inner reference, Rust takes `model.{model.k`. Both are refused at the parse; pinned.
