## Context

Eric asked for a review of a contributor's two Playground PRs, #570 (content-driven node width) and #571 (PNG and SVG export of
the graph view), and the Rust deploy twin of #570 (mercury #389). The review found no correctness bugs; it raised four points:
the SVG renders blank outside a browser (its node cards are HTML in `foreignObject`), #571 had no Rust deploy, Firefox and
Safari were never exercised, and a save failing after Chromium's dialog leaves an empty file. Eric's rulings: ship PNG only,
make the Rust PR carry the combined bundle, run the Firefox and Safari experiments here, and delete the empty file when the UI
can detect it.

## What was done

- **Stacked #571 on #570** by a merge (no force push to the contributor's fork branch): `pr-570` merged into
  `feat/playground-graph-export`, the bundle conflict resolved by regenerating. So #571's bundle is the combined one. After #570
  squash-merges, #571 needs `main` merged in once more, and the orphan `index-QRtKBTvK.js(.map)` that merge brings back from
  `main` must be deleted, because the branch no longer has it.
- **PNG only.** `graphImage.ts` lost `toSvg`, `withSolidBackground` and the format type. `graphImageFileName(graphName)` and
  `renderGraphImage(viewport, bounds, background)` are PNG-only. The toolbar's two-item menu became one **Export PNG** icon
  button, so its focus handling and menu CSS are gone. `saveImageFile(render, fileName)`. The tests, the four webapp docs and
  CHANGELOG Added 5 were updated.
- **The empty file.** In `saveFile`'s dialog path, a render or write failing after the dialog aborts the writable and calls
  `removeIfEmpty`: `handle.getFile()`, and when the file has 0 bytes, Chromium's non-standard `FileSystemHandle.remove()`. A file
  the user chose to overwrite that still holds its old content is kept. A browser without `remove()` keeps the file, and the
  save's own error is the one reported. Five new `saveImageFile` tests cover this.
- **Safari finding, fixed:** the experiments showed a solid grey block beside every node card in Safari's PNG. The cause is the
  cards' inline `box-shadow: 0 2px 8px rgba(0,0,0,0.45)` (`minigraphNodeTheme`): WebKit paints a blurred shadow inside the
  export's `foreignObject` as a hard rectangle. Injecting `box-shadow: none` cleared the block; that confirmed the cause before
  any code changed. The fix is `.graphSurface[data-exporting] .react-flow__node { box-shadow: none !important }`, so the image
  draws flat cards in every browser. After the fix, the share of non-white pixels is the same in Firefox and Safari (40.4% for
  tutorial 12, 21% for tutorial 14); before it, Safari's figures were 42.6% and 22%.
- **Rust #389 updated** to the combined bundle by `MERCURY_RUST_REPO=<worktree> npm run release:all`. `index-CWNizJaH.js` became
  `index-Ce3GNaH4.js` and `index-DaTDFwQo.css` became `index-BH572KKk.css`. The chunk, the stylesheet, the entry page and the 44
  help pages are byte-identical with the Java branch. Its CHANGELOG (Changed 2 plus a new Added 2) and Increment 183 now cover
  both changes.
