## What was done (branch `feature/minimalist-jsonpath`, off `main` `89cb2ea1`)

- **The module.** `system/minimalist-jsonpath`, package `org.platformlambda.mini.jsonpath`, `java.base` only. Its pom
  follows minimalist-msgpack's, with the same 90% line and branch gate. The root pom lists it after minimalist-msgpack.
  The main code is 2,257 lines with headers and javadoc:
  - `JsonPath`, the public API: `compile`, `compileLenient`, `select`, `selectPaths`, `read(document, notFound)` and
    `isSingular`;
  - `JsonPathException`, an `IllegalArgumentException` carrying the reason, the position and the query;
  - a recursive descent `Parser` for RFC 9535's appendix A, applying the type rules of 2.4.3 at compile time, with
    nesting limited to 64 levels;
  - the model classes `Query`, `Segment`, `Selector`, `Expr`, `Operand`, `FunctionCall` and `JsonFunction`, and
    `Values` for equality and order;
  - `Node`, which records each node's location, so results can also be given as normalized paths;
  - `IRegexp`, the RFC 9485 translator, and `HyphenNames`.
- **Two findings that shaped the code:**
  - **`^` and `$` in I-Regexp.** My reading of RFC 9485's grammar made them ordinary characters, but the suite's
    "explicit caret" and "explicit dollar" cases read them as anchors, as `serde_json_path` does. They map to `\A` and
    `\z`, never to Java's `$`, which also matches before a final line terminator.
  - **The hyphen rule is Eric's "follow Rust".** `compile` is RFC 9535 alone. `compileLenient` retries a refused query
    once through `HyphenNames.bracketize`, a step-for-step port of Rust's `bracketize_lenient_segments`: Rust's
    alphanumeric definition, quote tracking without escapes, and the rewritten query keeping the original text. So
    the suite runs against the strict engine with no deviation, and its `$.a-b` refusal holds.
- **Mercury's result shape.** `read()` mirrors Rust's `path_shape` and `misses_a_member_name`: a definite path yields
  the value or not-found, and anything else a list, unless a name step of the definite prefix misses. The prefix is
  computed from the parsed query, not by rescanning the text.
