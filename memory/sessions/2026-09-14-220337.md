## Distributed-cache spec: connection model clarified (single shared connection, no pool)

Eric's question — does the Redis client need a connection pool with Lettuce? — resolved to NO.
Lettuce is thread-safe and multiplexes: many threads pipeline commands over one TCP connection
and Lettuce correlates the in-order replies back to each caller (Redis needs no special support —
it executes/replies per connection in arrival order, the RESP contract; TCP is a serialized
conduit, as Eric noted). A pool would only be needed for blocking commands (BLPOP/WAIT) or
MULTI/EXEC — the cache op set has none (LPOP not BLPOP; append-with-TTL is a single EVAL).
