**Title:** The Playground's Graph tab exports the whole graph as a PNG or an SVG image

## Context

A contributor asked for two separate pull requests (PRs) on the Playground's graph view. This one adds an image export of the
graph visualization; the other one (branch `feat/playground-node-width-by-wrapping`) widens a node whose text wraps heavily.
Both rebuild the webapp bundle, so whichever PR merges second needs one more `npm run release` to resolve the bundle conflict.
The request: an "Export PNG" and an "Export SVG" action in the Graph toolbar that save the WHOLE graph, not the visible part,
with a solid background and the graph name in the file name; edges, edge labels and node text in the image; the minimap, the
controls and the selection outline out of it. A new npm dependency ships inside the engine jar and goes through the field's
security scans, so either avoid one or name it, its license and the reason in the PR.

## What was done

- **The menu.** `GraphToolbar` gains an **Export image** icon button between Download and Copy (a picture icon, `ImageIcon`).
  It opens a two-item menu, **Export PNG** and **Export SVG**, anchored under the button and styled like the canvas context
  menus: the first item takes focus, Escape closes it and returns focus to the button, an outside pointer down closes it. The
  button is disabled without a graph and while an image renders (`exportingImage`).
- **The renderer: `html-to-image` 1.11.11**, React Flow's documented approach - it copies `.react-flow__viewport`, inlines
  every element's computed style and wraps the copy in an SVG `foreignObject`; the PNG is that SVG drawn on a canvas. The
  viewport holds only edges and nodes, so the minimap, the controls and the dotted background (its siblings) never appear.
  **Why a dependency and not our own code:** the alternative is re-implementing the style inlining (computed styles, pseudo
  elements, fonts, images), about what the library is; a pure-vector SVG drawn from the graph data would have to re-create the
  node cards' text wrapping and would drift from the screen. **Why exactly 1.11.11:** React Flow's example pins it, and the
  upstream issue bubkoo/html-to-image#516 (open, no fix) reports that 1.11.12 and 1.11.13 draw styles wrongly. MIT license, no
  dependencies of its own. The main chunk grows from 683.81 kB to 700.60 kB minified (+16.8 kB; gzip 204.38 → 210.45 kB,
  +6.1 kB), the library and the new code together.
- **`utils/graphImage.ts`** (new): `graphImageFileName` (`<graph-id>.png|svg` from `suggestGraphId`, as Download names its
  file); `unionRects`; `graphImageFrame` - the bounds at zoom 1 with 40 px padding (size rounded up, a `translate` transform),
  so one graph pixel is one image pixel and nothing is scaled to fit; `edgeBounds` - `getBBox()`
  of every `.react-flow__edge` group (graph coordinates), joined with the node bounds because a back edge curls outside its
  nodes; `includeInGraphImage` - filters handles (the authoring halo included), resize controls and the box-selection rectangle;
  `resolveBackgroundColor` - the first opaque background of the viewport or an ancestor (white, `--bg-primary`);
  `withSolidBackground` - a full-size `<rect>` first in the SVG, because the library paints its background on the copied
  viewport, which the frame's transform moves; `renderGraphImage` - `toBlob` at pixel ratio 2 for the PNG (the library fills
  the canvas with the background), `toSvg` plus the rectangle for the SVG.
- **Selection styling.** A selected node's outline and a selected edge's colour are CSS rules the copy inherits through computed
  styles. `GraphView` sets `data-exporting` on the graph surface for the length of the render (`flushSync` first), and the three
  selection rules in `GraphView.module.css` now apply only `:not([data-exporting])` (the node rule was global; the only React
  Flow instance lives in the surface, so scoping it changes nothing else).
- **Save order.** `saveImageFile(render, fileName, format)` in `utils/graphFile.ts`: the native "save as" dialog opens BEFORE
  rendering, because the browser opens it only shortly after the click and a large graph can take longer; a cancelled dialog
  renders nothing; without the dialog (non-Chromium browsers) it renders, then downloads. `saveFile` takes the content or a
  function producing it; the existing text, YAML and binary saves are unchanged.
- **Wiring.** `GraphView.handleExportImage` (instance bounds + edge bounds → render → save), callbacks
  `onExportImageSaved`/`onExportImageError` through `RightPanel` (`onGraphImageSaved`/`onGraphImageError`) to `Playground`'s
  toasts "Image saved as `<file>`" and "Image export failed: ...".
- **Docs:** `webapp/docs/graph-view.md` (a new *Image export* section, the props, the toolbar line), `components.md`,
  `hooks-and-state.md`, `build-test-deploy.md` (270 packages; where a non-vendor dependency lands). The README lists no Graph
  toolbar actions, so it is unchanged. CHANGELOG Unreleased Added 5.
- **Bundle:** `npm run release` (Java only): `index-CWNizJaH` → `index-BHIrp40r` (and its map), CSS `index-DaTDFwQo` →
  `index-B3YhgMnt`, `template/playground.html`; the vendor chunks are byte-identical. Before the change a rebuild of the
  unchanged sources on Node 26 reproduced every committed file byte for byte.

## Notes for later

- No continuity fact yet: the dependency choice and its pin are this session's design, to be confirmed at review. If it
  stands, the fact to record is that the webapp bundles `html-to-image` pinned at 1.11.11 for the image export, and a bump must
  re-check upstream issue #516 and re-export a graph.
- The SVG is a browser format: node cards are HTML in `foreignObject`, and every element carries its full computed style
  (2.9 MB for nine nodes). A vector SVG for editors would draw the cards as SVG shapes and text - separate work, not asked for.
