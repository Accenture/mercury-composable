**Cause.** Node 25 turned its Web Storage API on by default. Without `--localstorage-file`, Node 26.10's `localStorage` global is an accessor that reads as
undefined and prints an ExperimentalWarning, while its `sessionStorage` is a working in-memory store. Vitest 4.1.11, the newest 4.x, copies a happy-dom window
property onto the global only when Node does not already define it or the name is on Vitest's own key list (`getWindowKeys` in
`node_modules/vitest/dist/chunks/index.*.js`): `Storage` is on that list, `localStorage` and `sessionStorage` are not. happy-dom binds both getters as own properties
of each window and makes each store with `new Storage()`, and nothing else in happy-dom reads those instances. Upstream, vitest-dev/vitest#10293 (merged
2026-07-01, shipped in Vitest 5.0.0) adds both names to the key list; the 4.x report, vitest-dev/vitest#10867, was closed as not planned.

**Fix.** `src/test/setupWebStorage.ts`, a `setupFiles` entry in `vitest.config.ts`: when `happyDOM` is on the global (Vitest's happy-dom environment), it defines
`localStorage` and `sessionStorage` as fresh happy-dom `Storage` instances without reading Node's getter, so no warning is printed; the `node` environment is left
alone. Chosen over `execArgv: ['--no-experimental-webstorage']` because Node 26 already lists that flag as an alias of `--webstorage`, and a Node that predates the
flag refuses to start with it. `src/test/__tests__/setupWebStorage.test.ts` pins the contract in three cases (both names are working happy-dom `Storage` instances,
and the two stay apart). It passes on Vitest's own storage as well, so it outlives the shim.

**Checked** on Node 26.10 with `NODE_OPTIONS` unset. On `main` with #493: `npm test` ran 43 files and 343 tests, all passed, no warning. Negative control (a scratch
config without `setupFiles`): 26 tests failed in 4 files, namely the 23 existing ones (`GraphMinimap` 8, `PlaygroundHelp` 7, four of which came with #493,
`useGraphData` 8) and the three new cases, with five warnings. The fifth came from `GraphViewControls`, which passed only because `useLocalStorage` catches the
`TypeError` (it reads `graph-nodes-compact`). Before the rebase, the old `main` gave 42 files and 324 tests passed with the fix and 22 failures without it (the
reported 19 plus the three new cases), and #493's branch with the fix copied into a scratch worktree gave 343 passed. Node 22 is not installed on this Mac (only
Homebrew's node 26), so `--no-experimental-webstorage` stood in for Node 22's web storage globals, which are none: 343 passed with the setup file and without it.
`npm run build` (typecheck, then `vite build` into `dist/`, no deploy) produced `dist/assets` (16 files) and an entry page identical byte for byte to the committed
bundle, so there is no release: the setup file is outside the app graph.

## Decisions Made

- A setup file rather than a Node flag (my call, stated in the PR): it works on every Node version and needs no feature detection. It replaces both storages, not only
  `localStorage`, so the `sessionStorage` tests run on happy-dom's store, as they do on Node 22.
- No Vitest 5 upgrade here: 5.0.0 carries other breaking changes (mocks cleared before each test by default, mutable window objects, a Node 22 minimum). The setup
  file is removed at that upgrade.
