## What We Did

- **Research before drafting:** the working store as built (Redis hash per conversation, compare-and-set, TTL per
  write, `retention` on a run the model ends), the loop spec's telemetry rule (no content) and its "audit is optional"
  paragraph, the concept's open Q4, what a turn knows (the host's trace context: `trace_id`, `trace_path`,
  `my_correlation_id`), what the loop forwards to `llm.chat` (the body; the correlation id rides as the platform's tag;
  nothing else), what `graph.task` sets on a request (`x-return-path`, and an author's `-> header.x-...` mappings), the
  mini-scheduler's pluggable-database precedent, the register's format, and the machine's Colima (0.10.3, docker CLI,
  no Compose plugin).
- **`draft-design-specs/transcript-audit-store.md` (RFC-0012, round 1):** two stores, two jobs - the working store's
  TTL is the transaction's expiry; a durable, append-only audit store keeps a conversation row and a turn row per model
  turn (trace id per turn, so a resume shows as a new trace under one correlation id; UTC times; model, status, stop
  reason, usage; the request message and the assistant content in the provider's format; the normalized calls; the
  system prompt and tools once on the conversation row). Written by the helper after the working store's
  compare-and-set (the engine never holds a transcript, ADR-0033); per turn recommended over end-of-run, because a run
  the loop stops is otherwise never audited; `required` or `best-effort` on a failed write; PostgreSQL first with the
  schema published (`transcript`, `transcript_turn`, indexes on correlation id, trace id and time, idempotent writes,
  `expires_at` for the installation's purge, writer and reader roles); configuration under `llm.transcript.audit.*`;
  `x-graph-id` and `x-node` from `graph.task` and the loop as an engine step; Colima + PostgreSQL 17 + pgweb scripts;
  eight rulings for Eric.
- **`draft-design-specs/agent-essential-tools.md` (RFC-0013, round 1):** a pack extension `extensions/agent-tools/`
  with `file.read`, `file.write` (`write: true`), `file.list` under `tools.file.root` and `web.fetch`, `web.crawl` under
  `tools.web.allow` (private ranges refused, redirects checked, sizes, pages and depth capped, `robots.txt` honoured,
  HTML to text in-house, no new dependency); a tool whose sandbox is not configured does not register, so the
  pre-flight check fails the graph before a token; rows published as files and by `describe`; the `site-notes` example
  (a crawl and a supervised write); the reference MCP servers kept as an installation's alternative behind the same
  routes; a generic `http.request` rejected; seven rulings for Eric.
- **`docs/arch-decisions/RFC.md`:** RFC-0013 and RFC-0012 entries (Proposal, Options, Resolution open), newest first.

## Decisions

- None taken here: both papers end in rulings for Eric. Recommendations made: per-turn audit writes; `required` as
  the default failure mode when an audit store is configured; PostgreSQL first with psycopg 3 and `pg` as optional
  extras; tools as a pack extension with in-house HTML-to-text and configuration-gated registration.
