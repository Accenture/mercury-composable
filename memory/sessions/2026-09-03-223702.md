`GraphCommandService.handleExportCommand` validated the graph's root `name` against the target
filename even when no name was declared, comparing a missing name as the string `"null"` — so an
unnamed draft could be exported once but never re-exported. Surfaced as friction by the

declared, mismatching name still rejects the overwrite — preserving the guard's original intent
(don't overwrite `graph123.json` with a graph named `graph100`).

## Durable lesson

**Inserting a method between an annotation and its target silently orphans the annotation.** My
new test landed between `@SuppressWarnings("unchecked")` and `syncCommand`, so the suppression
attached to the test instead — producing a dangling javadoc, a *redundant* suppression on the new
method, and an unchecked cast warning on the old one, all at once. Eric caught all three from a
Sonar screenshot. When inserting into a class, check what sits immediately above the insertion
point.
