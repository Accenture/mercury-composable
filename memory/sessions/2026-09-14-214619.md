- MPUT design (Eric's question drove it): a bulk write over a Map is a **pipelined per-entry SETEX**,
  NOT raw MSET — MSET sets no TTL, which breaks the "every key carries a TTL from birth" invariant.
  Per-entry SETEX keeps per-key TTLs, is single-key so cluster-safe (each routes to its own slot),
  and is non-atomic across the map (correct for a cache; a truly atomic multi-key write hits
  CROSSSLOT on a cluster anyway). Confirmed to Eric that each map entry is its own top-level cache
  key (so MGET reads them back); a whole-map-as-one-unit would be a Redis Hash (deferred).
