## What happened

Two graph-view improvements on branch `feat/playground-console-toggle` (Eric's requests):

1. **Console hide/restore toggle** (earlier this session): a `Console` button in the header
   (`Playground.tsx`) conditionally renders the left panel + separator so the graph view can
   take the full window width; persisted `console-panel-open` localStorage flag; restore-scroll
   effect because useWebSocket's auto-scroll only fires on new messages; `.clipboardToggle`
   CSS renamed `.panelToggle` (shared by Console/Workspace toggles).

2. **Node overlap elimination.** Diagnosis: `transformGraphData` set a fixed `height`
   (`nodeHeightForHandleCount`, typically 100px) on every React Flow node, so real content
   (measured 200–440px in tutorial-12) was hard-clipped by `.content { overflow: hidden }`;
   older bundles rendered content-height nodes over estimate-based positions — the overlap
   Eric screenshotted. Fix, three parts:
   - **Content-driven heights**: nodes no longer get a fixed `height`; `initialHeight`
     (content-aware estimate: header 40 + per-row 9 + 18/wrapped-line at 22 chars, calibrated
     within ~3px on tutorial-12) sizes the pre-measurement paint, `style.minHeight` keeps the
     handle-count floor. React Flow v12 drops `initialHeight` from inline styles after
     measurement (`getNodeInlineStyleDimensions`), so the DOM height follows content. A fixed
     `height` is only reintroduced by the user via NodeResizer.
   - **Measured re-layout**: new export `computeMeasuredPositions(data, measuredHeights)`
     re-runs the layout pipeline with real heights. GraphView applies it once per graphData
     when every node has `measured.height`, then re-fits via an `onInit`-captured instance.
     Guard for the refresh stale-window: each RF node's `data.properties` must be
     reference-identical to the current graphData node's (the transformer passes it through
     by reference; parsed payloads always allocate fresh objects). The done-ref also keeps the
     relayout from fighting later NodeResizer/drag changes.
   - **Bounded intrusion relief** (`relieveNodeIntrusions`, computeLayout step 4.5): with
     content heights a tall node (tutorial-4's 301px decision) is a wall no slot ordering
     routes a long edge around. Each pass finds the canonically-first remaining forward-edge
     intrusion (via `forwardBezierYRangeOverNode`, refactored out of
     `forwardBezierIntersectsNode`; offsets from the extracted `deriveFlowHandleOffsets`)
     and shifts the intruded node's column chain vertically by the minimal clearance
     (margin 16, ≤8 passes, gated by the same `collectGeometryPairs` budget as scoring so
     adversarial-scale graphs skip it).

3. **Thumbnail / expanded node toggle** (Eric's follow-up): a `ControlButton` inside the
   React Flow `Controls` (bottom-left, with +/−/fit) switches `graph-nodes-compact`
   (localStorage). Thumbnail mode renders header-only cards: `transformGraphData` takes a
   `compactNodes` option that stamps `data.compact` (MinigraphNodeBody skips the body) and
   swaps the estimate base to `NODE_HEIGHT_COMPACT` (48; handle floors still apply).
   Toggling re-enters the same measure-then-relayout cycle as a fresh load — verified in the
   lib: `adoptUserNodes` resets internal `measured` for replaced node objects, so every node
   re-reports dimensions. The relayout done-key became (graphData, compact) and the
   stale-window guard additionally requires `node.data.compact` to match; fitView now runs
   on every completed relayout pass (not only when positions moved) because a mode toggle
   changes the graph bounds even when the estimate layout was already exact.

4. **Thumbnail refinements (Eric's feedback round):** (a) consistent presentation — every
   thumbnail is a uniform FIXED-height card (`COMPACT_NODE_HEIGHT` 100 = header ~40 + a
   1.5x-header body peek; handle floors still raise it), the body renders the first
   key-values clipped with a bottom fade (`.bodyPeek` mask); compact nodes carry a fixed
   `height` so the measured relayout no-ops in that mode. (b) The control icon is now a
   colored mini node-card built from HTML/CSS spans (`.detailToggleIcon`, primary-blue
   border + tinted header band + body lines when offering details) — the previous stroked
   SVG rendered as a dark blob because React Flow's controls stylesheet forces
   `fill: currentColor` on control-button SVGs; HTML spans are outside that rule.

5. **In-place node editor (Eric's redesign request):** Edit Node no longer opens the modal —
   a new `NodeEditPanel` takes over the LEFT panel slot (the console's space) as a
   "magnified node": accent ribbon mirroring the node header (icon + alias + type badge,
   colored live by the current Node Type via `getMinigraphNodeAccent`, new export), aligned
   key/value grid rows (`minmax(90px,130px) 1fr 1.6rem`), scrollable body (any number of
   properties), sticky ribbon/footer. Esc, Cancel, or a successful save closes the session;
   `consoleOpen` is never mutated — the editor merely occupies the slot, so the previous
   state (console or full-width graph) returns on close. Playground derives
   `nodeEditSession` from `graphAuthoring.state` (status open + action edit-node);
   `GraphAuthoringModals` returns null for edit-node (create node/connection keep their
   modals); the console restore-scroll effect now keys on `consoleVisible`
   (consoleOpen && no edit session). 4 new component tests (ribbon/accent, form change
   propagation, Esc-close incl. sending lock, sending state).

6. **Editor key presentation + reorder (Eric's follow-up):** the panel now mirrors the
   backend's own `edit node` listing — rows sorted ascending by key
   (GraphCommandService.getRawProperties parity: zero-filled single-bracket indices so
   [2] sorts before [10]) and array indices shown as the **[] append signature**
   (`input[0]`/`input[1]` → `input[]`; keys with >1 bracket segment stay absolute,
   mirroring normalizeKey). Round-trip is exact because `update node` clears the property
   set and MultiLevelMap.setElement("…[]…") appends in line order — row order IS the array
   order. New: per-row drag grips (HTML5 DnD, no library) reorder rows; after a drop the
   rows re-sort by key (STABLE sort → same-key groups reform with the user's new relative
   order inside the group; empty-key rows sink to the end). Validation now accepts `[]`
   segments (`PROPERTY_PATH_SEGMENT_RE`). Helpers exported from propertyRows.ts:
   `toDisplayPropertyKey`, `sortPropertyRowsByKey`. Live round-trip proof: dragged the
   second `input[]` above the first on fetcher, saved, re-opened — server rebuilt the
   array in the new order. Note: CDP-synthesized mouse drags do NOT trigger HTML5 DnD;
   verify with dispatched DragEvents (real user drags work natively).

7. **Console button vs open editor (Eric's catch):** clicking Console while the editor

   blocked while a save is in flight) and sets `consoleOpen` true. `aria-pressed` reflects
   actual visibility (`consoleVisible`), and the button carries an explanatory label/title
   while the editor is open.

8. **Create Node unified into the panel; NodeDialog deleted (Eric's direction: same

   the alias directly in the ribbon (live icon/accent/badge as the type is typed), edit

   backend: create accepts dot/bracket path keys incl. `[]` appends and multiline values
   (buildCreateNodeCommand now preserves multiline via `'''` — the backend parses create
   and update property lines identically), so validation dropped its create-only
   single-line and simple-key restrictions.
