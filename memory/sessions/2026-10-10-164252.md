## What We Did

- **Eric's ask:** with OpenAPI on demand in MiniGraph, improve `extensions/api-playground`, whose setup was manual (clone swagger-ui, copy
  `dist` into `resources/public`, build): a script in Python AND Node.js that fetches the latest Swagger UI into the folder, and the folder in
  `.gitignore` so the third-party code is never committed (open source, but a copy goes stale). Mid-turn: "clean the target folder before saving
  so there is no mix-n-match" - already the design; the README now says it plainly.
- **Source ruling (mine): the GitHub release**, as Eric's steps name it. The latest-release API gives the tag; `codeload.github.com/.../tar.gz/refs/tags/{tag}`
  is 1.7 MB, not rate-limited, and holds exactly the `dist` folder's files, so the scripts take `*/dist/*` and nothing else. The npm
  `swagger-ui-dist` package is the same content plus npm-only files (a denylist). **Found:** the tarball carries 17 of the 23 `dist` files -
  upstream marks `/dist/*.map export-ignore`, so a release tarball never has the source maps by the project's own choice; the app does not need
  them. Documented in the README.
- **The scripts** (`scripts/fetch-swagger-ui.py`, Python 3.8+ stdlib; `scripts/fetch-swagger-ui.js`, Node 18+ with global fetch, zlib and a minimal
  ustar/pax tar reader that honours git archive's 'g' and 'x' headers): `--version vX.Y.Z` pins a tag, `--target DIR` names a folder; the target is
  emptied before writing, with a guard - a non-empty folder holding no previous fetch (no `swagger-ui-bundle.js` or `swagger-ui-version.txt`) is
  refused, so a mistyped `--target` cannot wipe an unrelated folder; `swagger-initializer.js` is pointed at the sample `./yaml/demo.yaml` instead of
  the Petstore demo (a self-contained page, no outbound call from an enterprise desktop); `swagger-ui-version.txt` records tag, time and URL.
  **Both scripts produce byte-identical output** (17 files, 4,486,602 bytes at v5.33.1).
- **Fail fast:** the placeholder `public/index.html` is removed (a tracked file inside an ignored folder would show the fetched copy as a diff),
  `/src/main/resources/public/` is ignored in the module's `.gitignore`, and maven-enforcer 3.6.3 `requireFilesExist` on `swagger-ui-bundle.js`
  stops `mvn clean package` at validate with the fetch instruction (first enforcer use in the repo; the module is standalone, outside the reactor).
  Negative control: with the folder moved aside the build fails with exactly that message.
- **Verified live:** the 51 MB jar serves Swagger UI at `/` (title "Swagger UI"), the initializer loads `./yaml/demo.yaml`, the bundle answers
