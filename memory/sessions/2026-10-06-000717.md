## What We Did

- **The rule, in the open PRs (Java #508 `066e503b` + `cc9a7839`, Rust mercury #356 `bb3cbcbe`):** a graph holds no null property. Java
  `GraphModelGate.withoutNullProperties` filters a map entry whose value is null at every depth (list elements and empty collections kept,
  `"key": ""` kept); `GraphSet.pack` applies it before the checks and the pack, `GraphSet.read` to every graph it returns, and `toJson`
  no longer serializes nulls. Rust `model_gate::without_null_properties` is `platform_core::serializer::strip_nulls_always` - the transport
  serializer's strip without its switch, one implementation of the rule - applied in `graph_set::pack`/`read` and in
  `compiler::load_raw_graph`, which unifies deployment with Java: a deployed graph holding `"key": null` now compiles on Rust (it was
  refused with "value cannot be null"; Rust CHANGELOG item 16). Java's deployment already dropped nulls through `ConfigReader`.
- **The switch, checked: `serializer.null.transport` has no effect on a package.** It is read in exactly two places per engine - Java
  `SimpleMapper` (Gson `serializeNulls`, writing only) and `MsgPack` (event payloads); Rust `serializer::null_transport`, used by the
  envelope encoder. The packagers never write through them: the canonical packager writes with msgpack-core / rmp directly, the filter
  takes no config, the unpack writer is a private Gson / serde_json, and the Java CLI's one `SimpleMapper` call parses JSON (unaffected by
  `serializeNulls`). Pinned: Java `theNullTransportSwitchDoesNotReachThePackage` forks a JVM with `-Dserializer.null.transport=true`
  (SimpleMapper is a singleton), proves the switch took effect with `NullTransportProbe` (SimpleMapper keeps `"a": null`; without the
  switch it drops it), then packs a null-holding graph to the default run's bytes and unpacks it without nulls; Rust
  `the_null_transport_switch_does_not_reach_the_package` sets the override, shows the switched `strip_nulls` keeping a nil, and packs the
  same bytes.
- **Cross-engine:** a graph holding nulls packs to identical bytes in both engines (336, `f2517ea7…`; before, Java packed 345 bytes with the
  nils and Rust refused); the tutorials are unchanged (`4715598820261ca6…`). The interop report, CHANGELOGs, READMEs and Increment 158 say so.
