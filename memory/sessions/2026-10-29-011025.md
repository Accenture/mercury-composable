## Findings

- **The engine already has the convention.** `invocation.observer.include` (`InvocationObservers.RouteFilter`) treats an
  entry ending with `*` as a route prefix (`route.startsWith(pattern without the *)`), and any other entry as an exact
  match. The spec adopts the same rule, so one convention serves both lists.
- **One addition for safety:** `return.path.routes` refuses three kinds of entry at startup, by name:
  - a bare `*`, which would declare every route and undo the guard;
  - a `*` anywhere but at the end;
  - an entry whose fixed part is not a valid route name (`Utility.validServiceName`: lowercase letters, digits, `.`, `_`
    and `-`).

  Write the dot before the `*` so the prefix ends on a whole segment: `order.status.*` matches neither `order.status`
  nor `order.statuses`.
