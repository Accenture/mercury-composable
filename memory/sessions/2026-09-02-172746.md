## Incident: the orphaned memory commits (recovered)

Eric's earlier memory commits for the json-plugin round were missing from main — my own
suggested command chain had put `git commit` (memory) BEFORE `git checkout main && git
branch -D <feature>`, so each memory commit landed on the feature branch and was
orphaned when the branch was force-deleted. Found via reflog; recovered by cherry-pick
onto main (`65d5f1e1` Java, `94581d1c` Rust) and pushed (Eric delegated the push).
**Lessons:** (1) never sequence a suggested command chain so a commit lands before a
branch switch/delete — write the safe order instead of a hazard footnote; (2) when
"committed and pushed" doesn't match `git log`, check `git reflog` before anything
else; (3) forking release branches from origin/main decouples them from local-main
memory state entirely.

## Flaky CI test — diagnosed and hardened (PR #312)

Main's post-push CI run 33660347841 failed in
`EventStreamClientTest.selfRelayStreamsProgressivelyOutTheEdge` — a memory-only diff,
same code green an hour earlier. Root cause: the progressive-relay assertion used the
first-to-last arrival SPAN (≥300ms vs fixture pacing 0/250/500ms); a reader starting
~373ms late on a loaded runner observes queued frames coalesced (span 127ms) even
though delivery was progressive (buffered would be ~0ms). Fix: assert the **largest
consecutive-arrival gap ≥100ms** — survives a late start, still fails a buffered
relay. PR #312 merged (`c94b0b53`) before the release PR. Durable lesson: wall-clock
SPAN assertions on streams are load-sensitive; the max consecutive GAP is the robust
progressiveness discriminator.
