**Title:** The AI companion broker: the recommended way to start a human-AI collaboration, `POST /subscribe`, one copy

## Context

Eric, from demos with team members and field engineers: the recommended way to start is that the human starts the
MiniGraph application in a terminal (to see the log), asks the agent to start a persistent WebSocket connection with
the broker, and subscribes to the session id the agent hands over; the agent's session never times out, and a human
whose backgrounded tab was closed reloads and re-subscribes. A second path: the human's session first, the agent's
session a subscriber that keeps the draft when the human's browser closes. Eric's rulings in the same exchange: the
default idle timeout is 60 seconds (his first figure, 30, corrected); rename the broker the **AI companion broker**,
the script included; add `POST /subscribe` to the broker (the shipped broker could not subscribe, and `/sync` refuses
topology commands); keep ONE copy, in the starter template ([[conv-one-copy-of-shared-tooling]]).

## What was done (branch `feat/ai-companion-broker`)

- Checked first against the code: `websocket.idle.timeout` defaults to 60 (`WsRequestHandler`), the web UI pings every
  20 s; `GraphCommandService.resetSession` turns each subscriber of a closing primary into a primary (`setTargetId` to
  itself) that keeps its graph, the Rust engine's `reset_session` the same; `synchronizeGraph` copies a non-empty
  primary's draft to the newcomer, or the newcomer's into an empty primary. Both engines send the same topology lines.

  engine's lines (`Session <id> has closed` frees it and logs the handover hint); a reconnect clears both. The copies in
  the two examples are removed; their `scripts/README.md` run the template's.
