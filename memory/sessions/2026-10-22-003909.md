**Title:** A failed function is traced as a failure - `ProcessStatus.setExecutionTime` no longer resets the success flag

## Context

Found while building the live invocation observers (branch `feature/dynatrace-oneagent-compatibility`): the worker records the
execution time AFTER an exception (`getErrorProcessStatus`: `setException(...).setExecutionTime(...)`), and the setter set
`success = true`, so `ProcessStatus.isSuccess()` read true for a function that threw. The behaviour dates from `756a1333`
(2024-01-07, the virtual-thread integration). Eric asked for the fix here, as its own PR, unrelated to the OneAgent feature.

## What was done (branch `fix/process-status-success-after-exception`, off `main` `250970d9`)

- **Scope found first.** `WorkerHandler.getMetrics` writes `success` and the `exception` from `ps.isSuccess()`. The OpenTelemetry
  forwarder maps `success` to the span status (`TraceMetricsSpanData`). So every record the WORKER sends had a failure reported as
  `success: true`, no `exception` and an OK span: a fire-and-forget event, a reply-to callback (every Event Script task, which the
  task executor dispatches with a callback, not an RPC), a journaled route. An RPC was unaffected: the caller's inbox
  (`InboxBase.setTraceStatus`) builds that record from the status (>= 400 is a failure). The Rust port derives the outcome from the
  error (`platform.rs`) and was unaffected.
- **The fix.** The setter no longer touches the outcome. The `MappingExceptionHandler` branch, which skipped the execution time and
  recorded zero, now sets it.
- **Tests.** In `PostOfficeTest`: a fire-and-forget failure, a callback failure (each traced with `success: false`, status 400,
  the exception), and a handled failure that records its execution time (at least 10 ms). `ProcessStatusTest` has two tests.
  **Shown to fail without the fix:** with the main-code change stashed, the four new tests failed at exactly those
  assertions, while `rpcTelemetryTest` passed.
- CHANGELOG Unreleased Fixed 3, with an upgrade note: dashboards and alerts on `success` or span status now see failed flow tasks
  and async functions as failures.
