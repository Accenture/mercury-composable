# Session (2026-11-20T02:46:48.000Z)

**Agent:** Claude Code
**Title:** The mini-scheduler's `leader.election` over a service mesh retired - the state resolver's claim and the environment store are the one mechanism
**User:** Eric - "for the mini-scheduler, please retire the 'service mesh' feature. It is because the StateResolver and EnvironmentStore are sufficient for concurrent POD detection and prod/DR selection. The 'service mesh' configuration parameter is confusing an AI agent that it can mix-n-match service mesh with state resolver."

## What We Did

  cron file that still carries the key loads with a warning naming it as retired (4.12.31). `JobExecutor.prepareJob` lost
  the mesh branch (`EventEmitter.search` for peers, lowest origin id wins) - every firing goes through
  `readyToExecute`, the resolver's `expires`. The test cron file keeps `leader.election: true` as the fixture that proves
  the loader ignores it: SchedulerTest still finds every firing claimed through the resolver.
- **Docs:** the module README's "Other ways to pick one instance" became "One mechanism, not two"; the example's README
  and cron file drop the key and its comment block; the guide's "Leader election instead" section became "One mechanism,
  not two" (the two-keys paragraph, the keywords, the configuration table and the See-also link to the service-mesh
  page follow); the configuration reference drops the `leader.election` section and names the key retired in its
  Scheduler intro; `cron.scheduler` left the reserved names; `docs/llms.txt` lists one file key.
- **CHANGELOG:** Unreleased gains `### Removed` (between Changed and Fixed, Keep-a-Changelog order), one entry with the

  more than one instance; the released sections diff empty against the `v4.12.30` tag.
- **Verification:** mini-scheduler 22 tests, scheduler-example 15, ai-contract-provider passes; no line over 120 columns

## Decision

Two configuration switches that answer the same question invite a reader - an AI agent first - to combine them. When
one mechanism is sufficient (the claim for the instance, the environment store for the site), the other is retired,
not documented around. Not an ADR yet: proposed to Eric as a one-paragraph decision (or an amendment noted beside
ADR-0030, whose context paragraph names `leader.election` as an existing single-site mechanism).
