## Findings

1. **The switch collides with its settings (branch only).** `ConfigReader` loads a properties file into a
   `MultiLevelMap` with the keys sorted, so `dynatrace.oneagent=true` is replaced by the map holding
   `dynatrace.oneagent.log.context` and `.destination`, and the switch is silently lost. A `-D` system property is read
   first, so it works; the lab uses it. It is the only one of the 9 `@OptionalService` switches with dotted
   sub-settings. Proposed fix: rename it `dynatrace.oneagent.enabled`, like `redis.cache.enabled` and
   `sync.over.async.enabled`.
2. **`ManifestReader` reads OneAgent's manifest (released code, main).** With OneAgent attached, the first
   `META-INF/MANIFEST.MF` the class loader finds is OneAgent's, so `/info` reports version 1.347.64.20261021-162634 and
   the startup log says "Application name: oneagentjava.17". Every field installation running full-stack OneAgent
   reports the wrong application version. Proposed fix, a separate PR on main: prefer the manifest of the jar named in
   `java.class.path`.
3. **The negative control splits the rest of the flow.** `lab.audit` starts a new trace, as intended. Its reply to
   `task.executor` is tagged in the audit's new trace, so the Kafka publish and `lab.receipt` continue there. Options:
   the guide states the split, or a reply from an unlinked route keeps the caller's tag.
4. **No PurePath link across Kafka.** `lab-worker` is a separate Dynatrace trace. The adapter's tag is an envelope tag,
   and the Kafka path (`simple.kafka.notification`, `KafkaFlowConsumer`) does not carry envelope tags. The fix would put
   the tag in a Kafka header on publish and back into the envelope on consume, as Event-over-HTTP does.
5. **SDK warnings on deferred results.** There are two per order: "incoming inProcessLink received on already started
   path … is being lost". OneAgent's own Reactor support had already continued the path onto the completion thread,
   shown as `reactor.core.scheduler` under the `Mono`, so the adapter's in-process link is redundant there. It is noise
   rather than lost data in this setup.

**The installer stays out of the repository (Eric, 2026-10-23).** OneAgent is commercially licensed. Before, only the
lab's own `.gitignore` (uncommitted) ignored its download folder. The root `.gitignore` now ignores
`lab/dynatrace-oneagent/oneagent/` and any installer named `Dynatrace-OneAgent-Linux*`, `-Windows*` or `-AIX*`.
A bare `Dynatrace-OneAgent-*` was narrowed before the push: with `core.ignorecase=true` it would also hide a file such as
`dynatrace-oneagent-guide.md` on a Mac, but not on Linux CI. Checked:
- no branch's history holds the installer;
- no tracked file matches the new rules, `core.ignorecase` included;
- under `lab/`, only `.env`, the built jars, `target/` and `oneagent/` are ignored.

**My error, fixed:** a rebuild without `-am` packaged the released platform-core from `~/.m2`, and the apps failed with
`NoClassDefFoundError: …spi/InvocationObserver`. `lab.sh build` now always runs Maven with `-am`.
