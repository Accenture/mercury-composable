**E1 implemented — one Redis List mechanism for one-shot and streaming return

- **Store re-platform (D8):** `ReturnRouteStore` drops `response:{cid}`
  (SETEX/GET) for `queue:{cid}` — `RPUSH` store-first with the TTL refresh in
  the same server-side atomic step (a two-command Lua eval: one round-trip on
  the hot path, and a client crash between RPUSH and EXPIRE can no longer leave
  a TTL-less key), destructive `LPOP` drains, `LLEN` for the drain's
  lost-wakeup re-check.
- **Coordinator:** `deliver()` is now literally a terminal post; the one
  subscription serves both patterns (streams checked first, then pending
  requests); streaming siblings `beginStream(cid, sink)` /
  `finalDrain(cid)` / `closeStream(cid)`; drains serialized per cid by a
  per-entry flag held THROUGH terminal cleanup (no post-terminal delivery)
  with an LLEN re-check after release (no stranded segment when a producer's
  wake-up bounces off the flag). Sink failure closes the stream (producers
  orphan out).
- **Complete-in-place (D8's one behavioral adjustment):**
  `PendingRequests.complete()` no longer removes; removal lives in
  `awaitResponse`'s finally + `abort` (exhaustive). The await-by-cid
  early-arrival path now rides the lookup itself. E1 surfaced one genuine race
  the old non-destructive GET masked: a wake-up landing between the await's
  timeout and its final drain pops the segment and completes the future,
  leaving the drain empty — so the timeout path consults `future.getNow` after
  an empty final drain (noted in spec §4.7).
- **New public API:** `StreamResponder` (RedisConfig-constructed, no
  coordinator/subscriber/switch; `post` = append + route-check + publish,
  false = orphan → stop) and `StreamSegment` (compact-JSON envelope via
  SimpleMapper's compactGson — the default mapper pretty-prints, caught by a
  unit test). `PendingStreams` mirrors the bounded atomic registry.
- **Config:** `sync.stream.ttl.seconds` (1800), `sync.max.pending.streams`
  (1000); 4-arg convenience constructor keeps existing call sites compiling.
