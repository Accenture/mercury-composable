## What was found

- **The scanner reads the verbose graph.**
  - At `main`, Maven built with platform-core's direct ASM 9.10.1.
  - `dependency:tree -Dverbose` still showed `(org.ow2.asm:asm:jar:9.7.1 - omitted for conflict with 9.10.1)` under
    `accessors-smart`, and that is the node the scanner reported.
  - Eric's working tree excludes ASM from `json-smart` and `json-smart` from `json-path`. With it, no 9.7.1 node is left,
    either in platform-core or in a consumer resolved from the reactor (event-script-engine).
  - The IDE panel he screenshotted predated the exclusion; reloading the Maven project in the IDE should clear it.
- **`json-path` 3.0.0 and 2.10.0 both declare `json-smart` 2.6.0**, and `accessors-smart` 2.6.0 declares ASM 9.7.1. The ASM
  path is the only vulnerable node.
- **Spring Boot's BOM overrides transitive versions for consumers.** Every module's parent is `spring-boot-starter-parent`
  4.1.1.
  - Its BOM manages Netty (4.2.17.Final), which is why Mercury sets `netty.version` in 38 poms.
  - It also manages `json-path` at 2.10.0, so 34 modules resolve 2.10.0 while platform-core declares 3.0.0. That has been
    true since 4.4.0, and no scanner flags 2.10.0. It is raised as a thread rather than fixed here.
- **Vert.x 5.2.1 is built against Netty 4.2.19.Final** (its `vertx-dependencies` BOM). Mercury had 4.2.18.Final from #463.
  Vert.x patch releases have shipped Netty security fixes before (5.1.6, 5.1.8); 5.2.1's own notes were not found.
