- The proposal is less radical than it looks: GraphSuspend already persists
  `node = FROM` (predecessor-agnostic) and resume already continues along the persisted

- **Two latent divergences found in the shipped engine:** (A) docs/validator say "a
  plain edge into suspend is an unconditional suspension point" but the walker actually
  fans out (parallel checkpoint + continuation — incoherent); (B) a graph.math jump to
  suspend works today but resume then fans out ALL the decision's outcome edges. The
  re-design fixes both.
- **Back-compat is structurally cheap:** every valid v4.11.x model draws the checkpoint
  edge (gate-enforced), so edge-inferred redirect reproduces old behavior exactly;
  `suspend=true` degrades to a no-op (deprecation WARN recommended). The persisted
  record contract {cid, node, ttl, model, seen, run} is untouched — mixed-version
  fleets safe both directions.
- **The one semantic addition needing a ruling (R2): re-execute-on-resume for
  routing-skill suspension points** — a decision that routed to suspend re-runs on
  resume against the new input (not marked seen; marks not restored for it). This IS
  the wait loop without the RESET idiom; tutorial-14 would drop await-decision + RESET.
