  token stream; **`LlmStreamRelay`** (engine demo) forwards its reply lane + correlation

- Live: 25+ timestamped token batches over a ~2s Gemini generation rendered out the

- Design clarifications ratified by Eric: the REST edge's Accept header is OPTIONAL

  a mandatory opt-in (406 without). Disconnect safety is requestId correlation (late

### 3. Streaming reply lanes rotate (both engines, lock-step)

Eric's live regression run surfaced that every sequential stream re-picked
`async.http.response.stream.499`: the checkout pool was a LIFO stack (boot fill 0..499
left 499 on top; release pushed back on top). Per his ruling, checkout now ROTATES:
`releaseLane` → tail (`addLast` / Rust `VecDeque::push_back`), checkout from head —
sequential streams walk `.0`, `.1`, `.2` (live-verified, three traces mapped to three
lanes) and a released lane rests the full pool length before reuse (max separation from
straggler cleanup). Test pins flipped (`laneCheckoutRotatesThroughThePool` /
`lane_checkout_rotates_through_the_pool`); ADR-0018 amended with a dated refinement line;
both draft specs updated; Rust Increment 95.
