**Title:** the `EventOverHttpStreamTest` mock-peer flake: a refused bind on an ephemeral port, PR #607

## Context

A side session started from the #606 session. The test's `@BeforeAll`, `startMisbehavingPeer`, has failed CI three
times with "misbehaving-peer mock must start ==> expected: <true> but was: <false>": main runs 37399451830 and
37394954320 on 2026-10-06, and #606's run 41763880034 on 2026-11-04, which was re-run. Each failure takes the whole
`platform-core` module down with it. The brief asked for a readiness signal in place of the timed wait.

## Diagnosis - a refused bind, not a slow runner

The 2026-10-08-190305 log called this "a runner-speed wait, not a logic race". The evidence says otherwise:

- The test already waited on the listen callback, but only on success (`listen(port).onSuccess(latch::countDown)`).
  A refused bind left the latch untouched, used up the 10 s and logged nothing.
- All three CI failures stopped at the bound (10.07 s, 10.19 s and 10.26 s) on runners that were otherwise fast.
  `MultiLevelMapTest` took 9 ms, and `EventStreamClientTest`, the next class, bound its own mock (`listen(0)`) on the
  same Vert.x instance at once.
- `sse.mock.port=58586` lies in Linux's ephemeral range (32768-60999) and in that of macOS and Windows (49152-65535).
  The suite opens many loopback client connections, and both October failures came right after `RestEndpointTest`'s
  46 HTTP tests. A client socket can hold 58586 as its local port, and a wildcard bind on that port is then refused.
- Reproduced locally: a dual-stack listener on `*:58586` gives exactly the CI signature (1 test run, the same message,
  no bind error in the log). A listener on `127.0.0.1:58586` alone, or on IPv4 `0.0.0.0` alone, does not reproduce it
  on macOS: Vert.x binds anyway and three mock tests fail instead, so a macOS negative control must hold `::` with
  `IPV6_V6ONLY=0`.

## Built (branch `fix/eoh-stream-mock-port`, commit `400596ab`, PR #607)

- The wait now covers both outcomes: `listen(...).toCompletionStage().toCompletableFuture().get(30, SECONDS)`. An
  `ExecutionException` fails at once, naming the port, `sse.mock.port` and the cause. A `TimeoutException` says the
  listen reported nothing in 30 s.
- `sse.mock.port` 58586 → 28586, below every ephemeral range and used by no other test. It stays fixed, because
  `event-over-http.yaml` addresses the mock by `${sse.mock.port}` and `EventEmitter` has no setter for a target at run
  time (it reads targets from YAML only).
- No production change and no CHANGELOG entry (test fixtures stay out).
