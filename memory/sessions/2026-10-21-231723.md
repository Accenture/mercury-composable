## Context

Eric asked for a review of #572 (vite 8.1.5 → 8.3.5) and #573 (vitest and @vitest/mocker 4.1.11 → 4.1.12). Both are Dependabot
security updates. The repository's alerts API needs a token scope this login lacks, so the public GitHub Advisory Database was

- **#572:** Vite 8.1.5 was affected by GHSA-587h-7wmj-h5pm (high, a Windows existence-check bypass in `launch-editor`),

All of these are in the dev server or the test runner; none is in the shipped bundle.

## What was found and done

- **#573:** 490/490 tests pass, and a rebuild reproduces the committed bundle byte for byte. Merge as is.
- **#572:** 490/490 tests pass, but Vite 8.3.5 moves Rolldown 1.1.5 → 1.2.15, and the rebuild changes every JavaScript chunk. The
  runtime's CommonJS interop helper changed (`__toESM` now checks for an own `default`), the router vendor chunk is 4.6 KB
  smaller, and the CSS is unchanged.
  - **A/B test:** two engine jars, `main`'s bundle on :8086 and the rebuilt one on :8085, ran the same script in Chrome 156 and
    Firefox 158. The results were identical in each browser: the root path and the catch-all route (which lands on `/json-path`),
    tutorial 12 with 9 nodes and 9 edges, the Raw view's text, the help index and the graph-math page, 22 palette commands, the
    exported PNG pixel hash, and no console errors.
  - The Vite 8.3.5 dev server serves the app and refuses `/@fs/etc/passwd` (403). `npm ci` still installs 270 packages.
- **Eric chose option 1:** the rebuilt bundle is one commit on #572's Dependabot branch, which now stops auto-rebasing that PR. #572
  and #573 merge together cleanly. The same files are deployed to the Rust repo on `chore/playground-bundle-vite-8.3.5`
