## Report 1: a date as ISO text computed as arithmetic in a DECIMAL statement

- **Reproduced** through `POST /api/graph/{id}` on `main` with a probe that asserted nothing, each value sent as a
  JSON string and read by `{input.body.x} + 0`. The report's table held: `2025-07-15` gave `2003`, `2*3` gave
  `6`, `10-1` `9`, `(5)` `5`, `1e3` `1000`, `A4352` "Unknown identifier", `5 5` "Incomplete expression".
- **Wider than reported.** A numeric `COMPUTE` had the same defect (`2003.0`; `PI` gave 3.14159; `max(1,2)`
  gave `2.0`; a value carrying `>` made the statement answer a boolean). Inside a `DECIMAL` ternary test,
  `{x} >= {y} ? 100 : 0` over two ISO dates took the wrong branch: read as arithmetic 2025-07-15 is 2003 and
  2025-01-01 is 2023, so the later date compared as the earlier. A comma in a value changed the number of
  `round()`'s arguments. A value that did not parse was an HTTP 500. The Rust engine renders the same way.
- **Root cause.** `GraphMath.decimal` rendered with `substituteVarIfAny(..., false)`, and `compute` without a
  boolean operator the same: a text value inserted as written, then parsed. `compute` also chose
  `evalBoolean` or `evalNumber` from the rendered text.
- **The report's third ask, a failed evaluation logged as an error: no change.** On the REST path
  `GraphExceptionHandler` already logs it at ERROR; the INFO-only record is a Playground session.
- **The fix, #683.** `ExpressionSource` checks each value where it lands, used by `COMPUTE`, `DECIMAL`,
  `CONDITION` and `IF`; the rule is the fact `math-text-value-one-value`. Tests: `ExpressionSourceTest` (11)
  and `TextValueStatementTest` (8 over five fixtures `unit-test-text-value-*`; 5 failed against the unchanged
  statement code). Pages: the skills reference, the command catalog, the `graph-math` help page, the Playground
  bundle (one chunk, its map, the entry page), three claims, CHANGELOG Unreleased Fixed 8 with the READ note.
- **Merged** by the maintainer 2026-11-27T21:00:15Z, squash `c1bfc4fc2`, every check passing.
- **The Rust twin, Increment 220**, built after the merge: `math::expression_source`, the Java tests' cases one
