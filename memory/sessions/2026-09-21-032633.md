## Incident — a stash pop that was not mine (recorded, no damage)

While recording PR #435 I chained `git stash -q && git checkout main && git stash pop` from the release
branch. The tree was clean, so `stash` saved nothing and exited 0; `pop` then applied the repository's
PRE-EXISTING parked stash — Eric's `On feature/minimap-help-run-v2: eric local bundle churn + nanoid
lockfile bump (parked before PR-341 rebase)` — onto main, leaving three unmerged Playground UI paths and
three untracked bundle files. Recovery: `git reset --hard HEAD` on main (nothing of mine was in the
tree), the three untracked leftovers deleted by exact name, `git stash list` confirmed the entry KEPT
(the pop failed, so git preserved it) — main identical to origin, the stash exactly as parked. Rule
taken into personal memory: never chain stash/pop; check `git stash list` and the full `git status`
first, and never truncate a status to one line.
