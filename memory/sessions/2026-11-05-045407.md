## Context

Eric, after #614 merged: prepare the next PR before v4.12.29 - the scheduler example's `StateResolver` and
`EnvironmentStore` on MongoDB instead of the temp file system, an embedded MongoDB in the tests, and a standalone
MongoDB server under `helpers/` so a user can test-drive the example on a VDI that has no Docker. Why: the
mini-scheduler is essential to the field, and a worked example on a real MongoDB keeps developers from making
assumptions and creating tech debt.

## Decisions (Eric, 2026-11-05)

- **The embedded MongoDB is pure Java (`mongo-java-server` 1.47.0), in the tests and in the helper.** The real `mongod`
  (flapdoodle 5.0.0) is a first-run download from fastdl.mongodb.org - 80 MB on macOS arm64, 104 MB on Linux, 791 MB
  on Windows (the zip carries debug symbols) - which a VDI, CI and the field's pipeline would each have to reach.
  Eric, mid-turn: the example uses a very small set of MongoDB features, so the emulator is an excellent choice; the
  helper's README states it is purely for dev and testing in an environment without container support and emulates a
  subset of MongoDB only.
- **`helpers/mongodb-standalone` joins the root reactor**, like its siblings ([[conv-lab-outside-root-reactor]]: asked
  first, since a reactor module becomes a field scan target).

## What was done (branch `feat/scheduler-example-mongodb`)

- Spike first: driver 5.8.1 and Netty 4.2.19 against the emulator - the README's claim had one winner among 8
  instances in 300 fresh and 300 expired rounds, the holder's retry won again. The emulator has no sessions (the
  driver refuses a `ClientSession`, so no transactions) and no `hello` command; a bind on a port in use rethrows
  Netty's checked `BindException` from a method that declares none.
- `examples/scheduler-example`: `SchedulerDatabase` (the client at first use from `mongodb.uri`/`mongodb.database`,
  `majority` writes, a 2 s server-selection wait unless the URI sets one - the scheduler waits 3 s per answer -,
  closed through `Platform.onShutdown`, the hosts logged, never the URI); `StateResolver` the MongoDB worked example
  word for word, refusing an `expires` without `_origin`; `EnvironmentStore` one document; `ScheduleAdmin` reading
  `job_state`, filtering `_` keys and computing the elapsed time. The demo jobs moved from 15 s and 25 s to once a
  minute (seconds 0 and 30): the 30-second window needs a period above 39 s. Tests: `TestDatabase` starts the emulator
  on a free port, or uses `-Dtest.mongodb.uri` with its own `scheduler_test` database; `StateResolverTest` races 8
  instances 100 times; the file-race test retired.
- `helpers/mongodb-standalone`: `EmbeddedMongo` (127.0.0.1, `mongodb.port`, an injectable exit so the failure branch
  is tested with a real port conflict), `MainApp`, README, 5 tests.
- Docs: the example README (MongoDB section, multi-instance, cron), the mini-scheduler README (a pointer from the
  MongoDB worked example; its own unit-test sample keeps 10 s), the guide and the configuration reference (no longer
  "file-backed"); CHANGELOG Unreleased Added 5; `memory/instructions.md` lists the helper.
