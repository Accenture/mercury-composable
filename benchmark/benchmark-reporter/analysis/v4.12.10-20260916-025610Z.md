## Purpose

First milestone baseline since the retirement, and a regression check on the riskiest part of it —
collapsing `ServiceQueue`'s dual dispatch into one per-route virtual thread, which is the hot path
for every route in the framework.

## The line that matters

**Probe under background flood: p99.9 = 1.141 ms, max = 1.386 ms.**

This is the scenario the whole migration turned on — a latency-sensitive route measured *while* a
different route's spill runs. It stays sub-2ms at the tail, so spill is still landing off the shared
Vert.x event loop after the dispatch branch was removed. That is the property ADR-0024 commits to, and
this is now its standing regression signal: if a future change puts blocking work back on the shared
loop, this number is where it will show first, well before any throughput figure moves.

## Reading the one number that got worse

Callback-flood p99.9 rose ~8% (36.69 → 39.63 ms). Not a concern, and worth saying why rather than
waving it off: in that scenario latency is **queue-bounded by Little's law** — up to 2,000 in-flight
against 50 consumers — so the tail tracks backlog depth and throughput, not dispatch efficiency.
Throughput was flat (+0.4%), so the extra milliseconds are queue residency, and a run-to-run drift of
that size is ordinary for a scenario whose latency is dominated by how deep the queue happened to get.
The scenario is there to prove *stability and zero loss under overload*, which it did.
