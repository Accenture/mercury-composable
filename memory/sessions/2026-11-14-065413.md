## The live drive (2026-11-14, local time UTC+8)

Redis 7 in a container (colima), the Playground from a copy of its jar, the Python helper on 8086 then the Node helper on 8087
(`-Dllm.peer.port`), the key in the helpers' environment only. **Negative control first:** the Python helper with a deliberately wrong
key - the loop failed by name through the graph's handler (401 `authentication_error: invalid x-api-key` with the provider's request
id) in 1.35 s. Then, on Haiku 4.5 through the Python helper: the approval protocol (approval at turn 2 in 14.4 s - the session's first
call took 11.1 s - re-advice in 17 ms, the approved refund answered in 2.7 s, one trace of 33 spans for run 1 with the helper's turns
under the same id); a refused decision whose note the model acted on (it offered a replacement; the log `refused`); a delivered order
answered without approval; the streamed run (11 events in 4.8 s); the WebSocket run (closed 1000 after the result). The same five
drives through the Node helper on Haiku 4.5 gave the same shapes. Opus 5.5 through the Node helper: the protocol again (the resumed
turn read 1,252 cached tokens and sent 2 uncached; the pack's caching at work) and a three-turn watched run. Totals: 40 model calls
(one the deliberate failure), 3,839 output tokens, 28,795 uncached input tokens on Haiku, 40 uncached against 13,734 cached on Opus.

**The defect found, in the example's design, fixed in the round:** a resume with a decision for an unknown call id made the loop
refuse with 400 before any token (right), but `graph.resume` had consumed the record, so the next request ran fresh and the transaction
was lost while the pack still held the conversation. The graph now notes a pending approval in the handler and `triage-failure` routes
such a failure back to the `advise` checkpoint; verified live afterwards (re-advice in 31 ms with the error and the waiting call, then
the right decision completed). Recorded as [[graph-failed-resume-readvises]].

## Findings worth keeping

- A prompt is advice, a catalog mark is a rule: Haiku skipped the order lookup in two of five runs and Opus called the two reads in
  sequence where Haiku called them in parallel, and the write waited every time, because the hold comes from `write: true`.
- Caching depends on the model's minimum cacheable prompt: zero on every Haiku turn (995 to 2,310 input tokens, below the 2,048
  floor), in force on Opus (1,024 floor).
- A number crosses the packs in its own shape (`174.0` from Python, `174` from Node for one schema): a tool reads `Number`.
- A resume is a new run and a new trace; the correlation id, the conversation reference and the call ids tie a transaction together.
- The envelope's `calls` log covers the calls that one `llm.run` call answered, so the advice also exposes `answered`.
