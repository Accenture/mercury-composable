## The debate and the outcome

Eric first proposed one generic public `mcp.tool` route with the server and the tool named in the call and the
per-tool wrapper on the engine side; I showed it is ADR-0033's rejected alternative (c) with a rule attached (a catalog
row must never name it directly). Eric then proposed pushing the wrapper into the pack as a public tool route with the
MCP client fully encapsulated, and I took it further: a `preload` function per tool, bound in code through
`bind(server, tool, schema_sha256)`, the server file keeping servers only, no generic route at all - so ADR-0033 needs no
reversal. Two revisions of mine were accepted: no `mcp.` prefix on a tool's route (a tool may start as an MCP tool and
later be implemented another way, so the name must not carry the transport; `mcp.` stays the binding's own namespace),
and `DiagramRender` stays, its storage of the SVG being business logic of the graph.
