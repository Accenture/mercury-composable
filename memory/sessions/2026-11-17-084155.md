## What We Did

- **Why.** The packs met the asymmetry while wiring the transcript audit store's database password: a key moved from
  `application.yml` to a `-D` flag silently lost its substitution, and a credential had to travel on the command line in
  clear. `ConfigReader.get` returned a system property as written, before any `${...}` resolution; the Rust port and both
  packs mirrored it exactly, so it was engine parity, not a pack bug, and the fix is a parity change in all four.
- **The change (`system/platform-core/.../ConfigReader.java`).** `get(key, default, loop)` passes a system property's
  value through the same `resolveValue` step as a file value (the segment extraction and `reconstructFromVarSegments`,
  extracted into `resolveValue`); the base-config guard and the loop detection are unchanged. An environment variable
  with a default, or a reference to another configuration key, resolves at read time, so `-Dkey='${ENV_VAR}'` keeps a
  secret out of the process list and container `args` arrays, which do no shell expansion. The javadoc says so.
- **Test.** `ConfigReaderTest.systemPropertyValueResolvesReferences`: a default, a reference to another system
  property, `${PATH}`, an unresolved reference as no value, the cleared property gone. The whole platform-core suite:
  565 tests, 0 failures. Noted: `jsonReadTest` fails when the class is run alone with `-Dtest=ConfigReaderTest`,
  because surefire passes its `test` user property into the forked JVM as a system property and the fixture's key is
  `test` - an artifact of the single-class invocation, before and after this change; the full run passes.
- **Docs and record.** `docs/guides/configuration-reference.md` (the resolution paragraph), CHANGELOG Unreleased Changed.
  The twins: mercury (Increment 203), mercury-python and mercury-nodejs, the same day, each with its own PR; the packs

## Decisions

- A runtime override's value is resolved like a file value, in every runtime (Eric, 2026-11-17). The one compatibility
  edge, a `-D` value that relied on a literal `${...}`, is accepted: a file value never allowed it, and an unresolved
  reference without a default is no value, as in a file.
