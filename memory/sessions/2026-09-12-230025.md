**Finding 1 — platform-core bug (own fix branch):** the HTTP client
percent-encodes `:` in URI path segments (Utility.getEncodedUri →
URLEncoder form encoding), and Google-style `:verb` custom methods reject
`%3A` with 404 (proved by a local sink capture: the client sent
`...%3AstreamGenerateContent` while the identical curl got 200). RFC 3986
§3.3 allows `:` in a path segment (pchar). Fixed via `encodePathSegment`
(restore `:` after encoding; plain segments + matrix path portions; query/
hash/matrix values keep strict encoding), regression pins added; the sole
production caller is AsyncHttpRequest.getFinalizedUrl, so scope is
client-only. platform-core suite 485 green / 3 benchmark skips. Rust-parity
note recorded in the commit (client bugfix, not an Event Script surface —
no lock-step, but the Rust client deserves the same pchar check).

**Finding 2 — the producer contract applies to forwarders:** the bridge
