## What was done

- **The model namespace.** `POST /api/mock/{id}?namespace=model` takes a JSON object whose keys are model paths without the
  `model.` prefix and sets each as `model.{key}`, leaving the other model variables in place (body and header uploads replace
  their namespace; the model holds `model.cid` and must not be replaced). The REST edge (`UploadMockContent.checkModelVariables`)
  refuses a non-object, a name with an empty path segment (blank, a leading or trailing dot, `..` - `MultiLevelMap`'s syntax
  check drops empty segments, so a name of dots alone would have replaced the whole model), a null value, and a bad path
  (`validateCompositePathSyntax`'s reason quoted). Console: "Mock data loaded into 'model' namespace". Travels like the other
  namespaces to every member of a collaborative session.
- **Headers processed as a request's** (`GraphCommandService.loadMockHeaders`), mirroring what the code does to a real one:
  `HttpRouter` lower-cases every header name and `AsyncHttpRequest.setHeader` strips CR and LF; `HttpToFlow` seeds `model.cid`
  from `http.correlation.id.header` (default X-Correlation-Id), and the edge adds that header with a generated id when absent -
  here the instance's `model.cid`, which `instantiate` already guarantees; `GraphExecutor.liftIterationIndex` lifts
  `x-iteration-index` into `model.iteration_index`. Each derived value gets a console line ("model.cid = order-1001 (from
  input.header.x-correlation-id)"). The REST edge now refuses two header names that differ only by case. Not mirrored, on
  purpose: `x-flow-id` (routing plumbing) and the per-endpoint request-header transform (application config). The
  `instantiate graph` lines stay direct state-machine writes - they mock the state, the upload mocks the request.
- **The form** (`MockUploadPanel`): the two labels; **Model variables (optional)** rows - name, a type select (text, number,
  boolean, JSON; a boolean row shows a true/false select), value - validated inline by `modelRowIssues` (no name, a repeated
  name, an empty segment, a value that does not read as its type; JSON `null` refused). `useMockUpload` posts body, then
  headers, then model variables, so a variable the author names wins over one a header derives. The type select was explicit
  rather than inferring JSON from the text: `12.50` read as JSON would silently become the double 12.5, the money trap the
  DECIMAL convention warns about. The Upload tooltip and the Playground's form description name the model variables.
