second cluster's registry. Review against the current tree: the diagnosis matches exactly (`start()` → one codec → the

shape, presence = opt-in, package-private helper) with three additions: blank counts as unset (the `${ENV_VAR:}` idiom, as
for `schema.registry.url`); an info/warn line stating that the adapter decodes with its own identity, or that the opt-in
alone cannot switch schema features on; and the codec-ready log label `serdeOverrides=<n>` replacing `csfle=<boolean>`,
which read `csfle=true` for a bare identity override. Two consequences of the seam the field's write-up did not state, now
in the docs and the javadoc: a `schema.registry.consumer.serde.*` override reaches the deserializer's configuration and the
DEK-registry client CSFLE builds from it (where key access is decided) but NOT the codec's own schema-by-id lookups, which
keep the template's identity — a second template is the answer when the consume identity must cover those too; and the
consumer codec reads only its own prefix, so a `schema.registry.serde.*` KMS credential is repeated under it. Applied

engineered around) and [[kafka-mesh-opt-in]]'s opt-in posture; code reaches main through a PR ([[eric-code-changes-via-pr]]).
The field's "fails open, silently" wording does not describe this engine: with Confluent's default `onFailure=ERROR` a decode
under the wrong identity throws, and a decode failure here is a poison message, dead-lettered — only a rule set with
`onFailure: NONE` passes ciphertext through — so the guide says what happens here.
