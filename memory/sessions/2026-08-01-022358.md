**The field issue:** a parent flow cannot catch a subflow/subgraph/API-fetcher timeout.
4-reader investigation proved WHY: TTL propagation copies the parent's FULL ttl into
each child with a RESTARTED timer (never remaining time), so the parent's deadline
always fires first — and a flow's own timeout bypasses exception handlers by design
(TIMEOUT → abortFlow → 408 to the caller). Two decisive findings made the fix cheap:
the child→parent 408 error channel already works end to end (child abortFlow →
task.executor → handleFunctionException → task-level/flow-level exception handler), and
EventScriptManager already honors a numeric dataset ttl over the flow template.

**Eric's rulings:** propagation stays the DEFAULT (top-down impedance matching); the
