**Title:** A NoClassDefFoundError in the Playground example traced to a reactor build rewriting its jar; the WebSocket warnings name the exception type

## Context

While #581's CI ran, Eric tried the Playground example's JSON-Path page. When he closed the browser tab, the log showed:
- a WARN `Session ws.766870.1 exception - io/netty/handler/codec/http/websocketx/WebSocketCloseStatus`;
- log4j failing to print it: `NoClassDefFoundError: org/apache/logging/log4j/core/pattern/ThrowableStackTraceRenderer$Context$Metadata`;
- `NoClassDefFoundError: io/netty/buffer/FreeChunkEvent` as the Vert.x event loop thread exited.

He would not replicate it, and asked for an investigation to be on the safe side. He also noted that in normal use the app detects a
session close, and that this edge case threw instead.

## Findings

- **The cause was my third reactor `mvn -o verify`.** It repackaged `examples/minigraph-playground/target/minigraph-playground-4.12.25.jar`
  while the example was running from it.
  - The jar's change time (`stat -f %Sc`) is 16:08:47 local, and the first error is at 16:08:47.880.
  - The build log puts the repackage between its timestamped lines at 16:08:47.151 and 16:08:48.966.
  - The modification time could not show this: it is the reproducible-build timestamp, 1980-01-31.
- **No class was missing.** All four classes the errors name are in the jar's own libraries:
  - `WebSocketCloseStatus` and `AbstractChannel$AbstractUnsafe$6` (netty-codec-http and netty-transport 4.2.19.Final);
  - `FreeChunkEvent` (netty-buffer);
  - `ThrowableStackTraceRenderer$Context$Metadata` (log4j-core 2.26.1).

  A `ClassNotFoundException` from Spring Boot's `JarUrlClassLoader` for a class the jar contains is what a jar rewritten under a
  running JVM gives.
- **Why the failure waited for the tab close.** A class loads on first use. The JSON-Path page used classes that were already
  loaded, and the tab close sent the run's first WebSocket close frame. The handler never ran, so the idle check expired both
  sessions after 60 seconds (16:09:47 `/ws/json`, 16:09:57 `/ws/graph`).
- **Normal close detection is sound.** The close handler logs `Session ... closed (1000, ok)`. The last reactor run logged 45 such
  closes, and `SessionManagementTest` passed 22 of 22.

## What was done

Branch `fix/ws-exception-type`, at Eric's direction:
- **`WsRequestHandler`'s exception warning** logs `{type}: {message}`, the idiom of `AppStarter`'s serializer loader, so this
  warning would have read `exception - NoClassDefFoundError: io/netty/...`.
- **`PersistentWsClient`'s warning** does the same.
- **The Rust engine's `ws_server.rs`** logs a tungstenite error, whose `Display` already names the kind, so no Rust change.
- **CHANGELOG** Unreleased Fixed 5.
- **The gotcha** is recorded as `example-jar-rewritten-by-reactor-build`. Before a reactor build, an agent checks
  `pgrep -fl 'target/.*\.jar'` and says so rather than rebuild under a running example.
