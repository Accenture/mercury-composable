the primary and its subscribers (human operators or an AI companion) are equal partners; anyone can enter any command except the private `session`
command, and every member sees the others' actions. Branch `fix/playground-subscriber-run-controls` (commit `0fafd86a`; Eric opens the PR). The root log
`memory/sessions/2026-10-02-050449.md` holds the full verification.

1. **No role gate on the run controls.** `useGraphRunWorkflow` dropped `isPrimary` from `canInteract` and from the disabled reason ("Run the graph from the
   host session"). Both engines already run a subscriber's command through the primary and replay it in every member's session.
2. **A topology change still resets the run, now on the change.** The old reset fired whenever the session was not primary, on every render, so it would have
   reset a subscriber's run at each graph refetch; it now compares with the previous `isPrimary`, like the connection-epoch reset. `Playground.tsx` passes
   `sessionCollaboration.isPrimary`.
3. **Tests:** a subscriber instantiates, takes its own upload invitation, survives a graph refetch and runs; a subscribe and an unsubscribe each reset a Ready run.
