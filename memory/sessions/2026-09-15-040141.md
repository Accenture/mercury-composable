### 2. The L3 timeout hunt → a durable engine lesson

The graph compiled and traversed fully (decide → encode → cache-put, Redis PUT status=200), yet
every L3 call timed out. Root cause chain:

1. A `graph.task` OUTPUT-mapping LHS may only be a constant or a `result.` / `model.` / `<node>.`
   element (`GraphLambdaFunction.setFetcherOutputEntry`) — `input.*` is legal on the INPUT side
   only. My `input.body.id -> output.body.id` threw `IllegalArgumentException`.
2. The throw happened inside `Mono.create(sink -> pending.thenAccept(response -> {...}))` in
   `GraphTask.invokeTask` — captured by the unobserved CompletableFuture stage, sink never
   completed, **no error logged anywhere**; the caller waited out its TTL. (WorkerHandler's expiry
   timer only logs "Async response timeout" and disposes — it never answers the caller.)
3. Graph-side fix in the example: stage the id at the decision node
   (`MAPPING: input.body.id -> model.id` — graph.math MAPPING uses the unrestricted
   `getLhsOrConstant`) and echo `model.id -> output.body.id`.
