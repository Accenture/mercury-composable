## Summary

- **The request (Eric, 2026-11-17, from a field installation):** the `DECIMAL` statement of `graph.math` had no
  configurable number of decimal places; proposed a default in `application.properties` (`big.decimal.precision=6`)
  and an optional `precision` parameter on a `graph.math` node. Eric added mid-session that an updated ADR must
  supersede ADR-0025, and the rationale: the field's financial calculation takes inputs from several sources, each
  with its own number of decimal places, so a consistent rounding policy is needed.
- **What ADR-0025 said:** "no graph-level mode, no application default and no CompileGraph check" - the feature
  amends an accepted decision, so ADR-0034 was written and ADR-0025 marked Superseded in place (its statement, exact
  arithmetic, canonical strings and comparison rule stand; only the "no application default" clause falls).
- **The semantics chosen (my ruling, declared for Eric's review):** the limit is a CAP with HALF_UP - a result with
  more decimal places is rounded to the limit, one with fewer keeps its computed scale, so the limit never pads and
  every result within 6 places is byte-for-byte what ADR-0025 produced. Applied once, at the statement's result in
  `GraphMath.decimal` through `DecimalEvaluator.evaluate(expression, maxScale)`, never inside the arithmetic
  (`1 / 3 * 3` rounds to `1.000000`); `evaluate(expression)` stays unbounded so the shared conformance vectors are
  unchanged. A `round()` to more places than the limit is rounded again - declared, the node raises its `precision`.
  `precision` is a whole number from 0 to 1000 (`DecimalEvaluator.MAX_SCALE`, now public); `GraphModelValidator`
  rejects a malformed node value at deploy, a malformed application value fails the first statement naming the key.
  An `EXECUTE`'d module takes the calling node's limit. The name `precision` is the field's word; the dialect's
  `round(x, scale, mode)` keeps `scale` for the same quantity - flagged, not changed.
- **Code:** `DecimalEvaluator` (`evaluate(String, int)`, `limitScale`, `precision(Object)`), `GraphMath`
