## What We Did

- **The ask (Eric):** is it viable to generate a minimal OpenAPI 3.0 document per graph on demand (`GET /api/openapi/{graph_id}`,
  downloadable), given that the Playground's instantiate-upload-run feature resolves a graph's input parameters, and with
  `extensions/api-playground` (a Swagger UI host for OpenAPI files, outside the reactor, swept at releases) as the consumer?
- **Findings.** Both engines already derive the contract: `describe graph {id}` scans every node's properties for `input.*` and
  `output.*` path tokens (Java `GraphCommandService.collectModelSurface`, Rust `commands::model_data_surface`), sorted and byte-identical
  across engines; the webapp's own upload hint (`graphRun/graphInputPaths.ts`) is a browser-side `input.body`-only copy of the same rule.
  The HTTP request reaches a graph as `input.body`, `input.header`, `input.query`, `input.path_parameter` (the flow adapter's dataset,
  copied whole into the state machine by `beginTraversal`); the response is `output.body`, `output.status` (staged by `int(N) ->
  output.status`) and `output.header.*` (`executionComplete`). Measured over the bundled models with a throwaway scanner (scratchpad):
  14 tutorials — 13 read `input.body`, 2 pass the whole body through, none reads a header or query parameter, 9 name `output.body.<field>`
  paths, 5 set the whole `output.body` from a task result; of 57 output mappings 15 carry a type (12 constants, 3 known plugins), of 31
  input references 2 do; 65 engine test graphs — 36/9/1 and 36/15; 31 of 153 output mappings typed, 9 of 79 inputs. So the shape comes
  free and the types come only where a mapping says so; MiniGraph has no requiredness. YAML emitters exist on both sides (SnakeYAML in
  platform-core; the Rust `yaml_serde` 0.10.7 exports `to_string`); the attachment response shape is `PackGraphSet`'s; a dev route is
  five Java and three Rust `rest.yaml` copies; `/api/openapi/{graph_id}` does not collide with the executor's pattern; the dev routes and
  the executor route carry the wildcard CORS entry, so Swagger UI's Try it out from the api-playground reaches the engine. A sketch
  generator produced the tutorial-4 and tutorial-14 documents from their models alone (untyped leaves as `{}`, the `404` from the
  staged status).
- **Eric's design, in four turns:** (1) expand the "declared schema" option — an optional input schema on the root node and an output
  schema on the end node; the system discovers and pre-populates as much type information as possible and the developer fills in the
  rest; the UI makes that easy for a developer or an AI agent. (2) Validation: a root schema makes input validation possible, invoked by
  the traveler and the executor when the root loads, with a minimal set of OpenAPI 3.0 syntax (`required`, `min`, `max`). (3) The
  property is named `schema` on both nodes (the node says which side). (4) Nothing is inserted into the root node: the validator is
  ASSUMED by the engine, so there is no chance of a typo; it runs when the graph runs, and a root node's own skill runs after a successful
  validation. My adjustments, agreed by Eric: no file rewrite at export (one source of truth); the vocabulary is OpenAPI 3.0 keywords by
  their OpenAPI names (`minimum`/`maximum`, so the declaration embeds verbatim) as a CLOSED subset the gate refuses to exceed — a
  constraint the validator silently ignores would teach that unflagged means safe; strict JSON types; `pattern` after `maxLength`, in the
  regex subset common to Java and the Rust crate; every violation up to a cap in one 400 message; the end schema documentary.

## Decisions

- Eric: `schema` on the root (input) and end (output) nodes; the validator assumed, never inserted; it runs first at the root on every
  run and a root skill runs after a successful validation; OpenAPI 3.0 syntax as the vocabulary.
- Agreed adjustments: closed keyword subset refused by the gate; OpenAPI keyword names; strict JSON types; one 400 with every violation;
  the OpenAPI document a derived artifact, never stored; validation at the root only, the end schema documentary.
