**Title:** The application's version comes from its own jar, also under Dynatrace OneAgent

## Context

The OneAgent sandbox run (2026-10-23-005210, finding 2) showed every application under full-stack OneAgent reporting
OneAgent's identity. The startup log said "Application name: oneagentjava.17", and `/info` reported version
`1.347.64.20261021-162634`. Eric: "please fix ManifestReader to get the correct version - a separate PR is fine". It
is released code, so it has its own branch from main (`72393a00`, which includes #584),
`fix/manifest-reader-application-jar`.

## The cause

`ManifestReader` read the class loader's first `META-INF/MANIFEST.MF`. Parent delegation searches the boot class path
first, and OneAgent puts its jar there.

## What was done

- **`ManifestReader.applicationManifest(classPath)`** reads the manifest of the jar that `java.class.path` names first,
  which is the application's jar for `java -jar`. Only the first entry counts, because the jars after it are libraries
  or agents.
- **A class path that starts with a folder** (an IDE, a test run), or a jar without a manifest, falls back to the
  class loader's first manifest, as before. The version and name logic is unchanged.
- **`ManifestReaderTest`** (3 tests, the first for this class) builds an application jar and an "agent" jar in a temp
  folder.
