**Title:** The mini-scheduler's environment name moves to `scheduler.environment.name`, so it can sit beside the store

## Context

While renaming the OneAgent switch on PR #583, Eric asked to "check the parameters so that they can coexist". A scan of
every configuration key found the same collision in released code. `scheduler.environment` (since 4.12.22, ADR-0030) is
both the instance's environment name and the parent of `scheduler.environment.store`. Eric: "the mini-scheduler and
scheduler-example need the same parameter renaming fix". It is released code, so it has its own branch from main,
`fix/scheduler-environment-name`. The OneAgent work and the scan are in 2026-10-23-215957, on the OneAgent branch.

## The defect

`ConfigReader` holds a key as a value or as child keys, never both. A probe with the real reader, both keys set in
either order, showed `getProperty("scheduler.environment")` answering `{store=my.store}`. `ActiveEnvironment`'s name
check then fails at startup with "scheduler.environment must be one word…". So any application that sets the store
fails, and none can depend on it today. The Rust port has no such setting.

## What was done

- **`ActiveEnvironment.ENVIRONMENT` is `scheduler.environment.name`.** `configuredEnvironment` reads it, then a plain
  value of the old key (`LEGACY_ENVIRONMENT`) with a deprecation warning, then `prod`.
- **When `scheduler.environment` holds child keys but no name, startup is refused with "Set
  scheduler.environment.name…".** Defaulting to `prod` there would be a silent regression: a DR site that keeps
  `scheduler.environment=dr` beside the store loses the `dr`, and as `prod` it would run every job in both sites.
  Today that setup at least fails at startup.
- The trace sender label stays `scheduler.environment`.
- `ConfiguredEnvironmentTest` reads three property files through the real `ConfigReader`: the name beside the store,
  the old key alone, and the old key beside the store (refused). A fourth case checks the default.
- **Docs:**
  - the configuration reference (the heading and its anchor kept, plus a paragraph on the old key);
  - both READMEs;
  - the example's `application.properties` and its `/env` list;
  - ADR-0030, with an inline amendment like the 2026-10-06 one;
  - CHANGELOG Unreleased Fixed 6, with an upgrade note.
