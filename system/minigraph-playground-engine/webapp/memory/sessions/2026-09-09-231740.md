1. **Layout storage key versioned** — `useDefaultLayout` id is now

2. **Session live-graph restore** (`useSessionGraphRestore`) — described
   temp-model paths (`/api/graph/model/…`) expire server-side about a minute
   after `describe graph`, so SPA-returning from JSON-Path re-fetched a dead
   path: HTTP 400, an error toast, and an empty canvas while the session
   still held the live graph. Now: `useGraphData` exposes an
   `initialFetchFailed` verdict (set on fetch failure AND on an HTTP-200
   error-envelope body — the backend can answer 200 with a non-graph JSON)
   plus a `quietInitialFetchFailure` flag that suppresses the toast where the
   restore owns the failure; the restore hook fetches
   `GET /api/graph/session/{id}` once per (session, pinned-path) attempt when
   the model path is a dead end or none is pinned, renders the result through
   the same `isMinigraphGraphData` guard + graph-tab auto-switch, and stays
   silent when the session has no live graph. The session id arrives via the
   mount-time `session` round-trip, so the hook reacts to its LATE arrival —
   the pinned fetch usually fails before the id is known. The pinned path
   re-arms on the next describe/mutation auto-refresh cycle (auto-refresh
   sends `describe graph`, which re-pins).
